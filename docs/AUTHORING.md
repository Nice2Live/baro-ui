# BBE UI — справка для авторов окон

Команда консоли — `baroui`; прежнее имя `bbe_ui` тоже работает (2026-11-16, переименование движка в BaroUI).

Окно — обычные `.html` и `.css` в папке `UI/` пакета; поведение — класс C# (роль JavaScript). Движок рисует сам, браузера в игре нет: поддерживается только то, что перечислено ниже. Всё неизвестное пропускается с замечанием в логе и на плашке ошибок (`baroui watch` или `baroui debug`).

Тест `tools/ui_test` (`AuthoringGuide` в `Program.cs`) проверяет только имена: каждое известное движку свойство и сокращение стоит здесь в обратных кавычках, каждый псевдокласс встречается здесь как `:имя`. Описание он не проверяет, а названия, которых в движке нет, не ловит: такие перечислены ниже в «Нет совсем» и в «Нет» у селекторов.

## Быстрый старт

```csharp
public sealed class FuelView : BaroUiView
{
    protected override void OnOpen() => Data = new { level = 40, rods = new[] { new { id = 1, name = "Стержень" } } };
    [UiHandler] private void refill(int id) { /* сообщение серверу, ответ обновит Data */ }
}
BaroUi.Open<FuelView>(Path.Combine(pkgDir, "UI", "fuel.html"));
```

- Холст страницы — **1600u × 900u**, по центру экрана. `1u = min(ширина/1600, высота/900) × масштаб HUD`.
- Деталь, которая висит на краю или в углу самого экрана (оповещения), просит весь экран вместо холста: `<html data-viewport="screen">` (или на `<body>`). Тогда вьюпорт раскладки — экран целиком, `position: fixed`, `right: 0` и проценты считаются от его краёв на любых пропорциях; единица `u` та же. Без атрибута страница, как раньше, на холсте по центру. Предпросмотр в браузере режим не показывает (рисует холст 16:9).
- Данные в `Data` (объект C# или словарь). После изменения объекта — `Refresh()`; точечно — `Set("ship.depth", v)`.
- Изменения игры (крафт, покупка) идут только через сервер; окно ждёт ответа и данные само не меняет.

**Окно предмета** (так сделан терминал, `own/BBE_Terminal/CSharp/Client/TerminalUi.cs`):

- `BaroUi.Create(path, view, name)` — окно не свободное: компонент сам добавляет его в список обновления из своего `AddToGUIUpdateList` (`window.AddToGUIUpdateList(order)`) и закрывает (`Close()`) при снятии выбора.
- Esc и клик мимо окна обрабатывает игра: `GuiFrame` компонента — невидимый `GUIFrame`, который каждый кадр ставится на прямоугольник корневого блока (`window.BoxOf(window.Find("term"))`).
- `baroui reload` и `watch` работают и для таких окон; кто хранит ссылку на окно, подменяет её по событию `BaroUi.Reloaded`.
- `window.CaptureNextDraw("x.png", "id")` — снимок блока после следующей отрисовки (самопроверки, сверка с макетом).

## Версия движка и публичный API

- Версия: `BaroUi.Version` (`System.Version`, сейчас 0.2.0) и `modversion` в `filelist.xml` движка — одно число. Консоль: `baroui version`.
- Мод проверяет её при старте: `if (!BaroUi.Requires("0.2.0", "Мой мод")) { return; }` — при старой версии одна строка в журнале и `false`.
- Что можно использовать снаружи, и что значит «ломающее» изменение (semver): `API.md`. Внутреннее (`internal`) менять можно без предупреждения.
- Готовый образец мода: `own/BaroUI_Example` (страница `UI/example.html`, вид `ExampleView`, консоль `baroui_example`, инструкция — `README.md` в папке).

## Единицы и значения

| Что | Поддерживается |
|---|---|
| Длины | `u` (основная), `px`, `em`, `%`, `fr` (в grid), `auto`, `0` без единицы |
| Цвета | `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, имена: `transparent black white red green blue yellow orange gray grey cyan teal magenta lime silver navy maroon purple` |
| Переменные | `--имя: …` и `var(--имя, запасное)`; наследуются, могут ссылаться друг на друга |
| Ключевые слова | `inherit`, `initial`, `unset`, `!important` |
| Картинки | `url("файл.png")` в `background-image`, `border-image-source`, `<img src>`; путь от папки страницы, не выше пакета (рядом с `filelist.xml`); `sprite(вид:id)` — спрайт игры. Адреса в сети, `data:` и абсолютные пути не принимаются (ничего не скачивается) |
| Шрифты | `@font-face` со страницы или её таблицы стилей: `font-family`, `src: url("файл.ttf")` (несколько через запятую), `font-weight`, `font-style`; `.ttf` и `.otf`. Раздел «Свои шрифты» |
| Нет | `calc()`, `rem`, `vw/vh`, `hsl()` |

## Селекторы

- `tag`, `#id`, `.class`, `*`, `[attr]`, `[attr=value]`, потомок (`a b`), ребёнок (`a > b`), следующий брат-элемент (`a + b`), любой следующий брат (`a ~ b`), список через запятую; комбинаторы смешиваются: `.x > .y + .z ~ li`. Специфичность от комбинаторов не зависит.
- Псевдоклассы: `:hover`, `:active`, `:focus`, `:disabled`, `:checked`, `:root`, `:first-child`, `:last-child`, `:nth-child(N|odd|even)`.
  - `:focus-within` — элемент с фокусом и все его предки (кроме корня страницы): `.field:focus-within { border-color: #40c8be }`.
  - `:dragging` (источник перетаскивания) и `:drag-over` (приёмник под ним, берущий вид): см. «Перетаскивание между блоками».
  - `:not(X)` — один составной аргумент без комбинаторов: `:not(.a)`, `:not([disabled])`, `:not(:hover)`, `a:not(.b):hover`. Специфичность — как у аргумента. Списки (`:not(.a, .b)`), комбинаторы внутри (`:not(.a .b)`) и вложенный `:not` не поддерживаются: правило пропускается с замечанием.
  - `.a:hover + .b`, `.a:hover ~ .b .c`: наведение на `.a` перестилает следующих братьев (для `+` — одного, для `~` — всех) и, если правило идёт дальше потомком, их поддеревья; вставка, удаление и перестановка копий `data-for` перестилают детей контейнера, которым может подойти часть после `+`/`~`. Смена `class`/`style` у элемента: `UiWindow.Restyle` перестилает и следующих за ним братьев, до которых достают такие правила (`StyleEngine.FollowingReached`); пачка изменённых элементов (`RestyleBatch`) перестилает каждого такого брата один раз, а вставка и удаление копий `data-for` (`RestyleStructure`) зовёт перестиль без прохода по братьям, потому что сама перестилает всех достижимых детей: цена линейная, а не квадратичная.
  - Смена состояния (наведение, нажатие, фокус) перестилает только то, что видит правило: сам элемент, а потомков — если правило с этим состоянием стоит в предке (`.card:hover .name`) или потомки наследуют изменившееся значение (`color`, `font-size`, `--переменная`). Правила `:hover` без нужды на предках страницы (`.page:hover …`) стоят дороже: при них весь предок перестилается при каждом входе и выходе указателя.
  - `:has(X)` — относительный селектор: элемент, у которого есть потомок под `X` (`.card:has(.x)`), ребёнок (`.card:has(> .x)`), следующий брат (`.row:has(+ .sel)`) или любой следующий брат (`.row:has(~ .sel)`); `.form:has(:checked)`, `.panel:has(:hover)`, `.a:not(:has(.b))`. Аргумент — один относительный селектор, в нём можно цепочку с комбинаторами (`:has(.a > .b)`) и состояния. Списки (`:has(.a, .b)`), вложенный `:has` и псевдоэлементы в аргументе не поддерживаются: правило пропускается с замечанием. Специфичность — как у аргумента. Смена класса, атрибута, состояния или состава детей перестилает только тех предков и предыдущих братьев, чьи `:has()` могут это видеть (`StyleEngine.AnchorsOf`); страница без `:has()` такой проверки не делает. Цена: `docs/ui/PERF.md`, «Псевдоэлементы и :has()».
- Нет: `[attr^=…]` и другие операторы атрибутов, `@media`, `@import` (`@keyframes` есть, см. «Анимации»; `@font-face` есть, см. «Свои шрифты»).
- Каскад как в браузере: `!important`, затем специфичность, затем порядок; `style=""` сильнее любого селектора.

### Псевдоэлементы `::before` и `::after`

- `.a::before { … }` (и старая запись `:before`) рисует коробку перед содержимым элемента, `::after` — после. Коробка лежит в раскладке как первый или последний ребёнок элемента, но сама не элемент: её нет в дереве, поэтому шаблоны, обработчики и запросы её не видят. Наведение, нажатие и попадание мыши на коробку — это наведение на сам элемент; коробка своих событий не принимает. Один псевдоэлемент на селектор и только в конце: `.a:hover::before` можно, `.a::before .b` и `::before::after` нельзя.
- `content`: строки в кавычках с CSS-экранированием (`"\201C"`), `attr(имя)` — значение атрибута элемента и `icon(имя)` — значок Lucide по имени (как `data-icon`, `Core/Icons.cs`; если правило не задало `font-family`, шрифт `lucide`). Части склеиваются подряд: `content: "№ " attr(data-id)`. `none` и `normal` — коробки нет. Прочее (`counter()`, `url()`) — коробки нет и одно замечание в журнале.
- Коробка стилизуется, как элемент: `display` (по умолчанию `inline`; `block`, `inline-block`, `flex` у её ребёнка и т.д.), `position: absolute` с `top`/`left`, `background`, `border`, `border-radius`, `box-shadow`, `width`, `height`, `padding`, `margin`, `transition`. Свойства, которые наследуются (`color`, `font-size`…), берутся у элемента. Состояния элемента действуют и на коробку: `.a:hover::before { color: #f88 }` меняется вместе с наведением на `.a`.
- Не поддерживаются: `::first-line`, `::first-letter`, `::marker`, `::selection`, `::placeholder`, `counter()`, `counters()`, `content: url(…)`. Пример: `own/BaroUI/UI/pseudo_demo.html`.

## Свойства

**Раскладка**

| Свойство | Значения и замечания |
|---|---|
| `display` | `block`, `inline`, `inline-block`, `flex`, `inline-flex`, `grid`, `inline-grid`, `flow-root` (блок, у которого поля детей не сливаются с его полями, как в браузере), `none`. `table`, `table-row`, `table-cell`, `list-item` — блоки без табличной раскладки, одно замечание в журнале |
| `position` | `static`, `relative`, `absolute` (`fixed` — как `absolute` от окна), `sticky`: блок держится у `top` / `bottom` ближайшего прокручиваемого предка (`overflow-y` не `visible`) и не выходит за свой родительский блок. Раскладка не меняется: двигаются рисование и мышь (одна и та же формула в `Core/ScreenMap.cs`). Без прокручиваемого предка блок не двигается. Для шапки списка: `#head { position: sticky; top: 0 }` в прокручиваемом блоке. Значения `top`/`bottom` — `px`, `u`, `em`, `%` от высоты прокрутки |
| `top`, `right`, `bottom`, `left` | для `relative`/`absolute` |
| `width`, `height`, `min-width`, `min-height`, `max-width`, `max-height` | длины, `%`, `auto` |
| `margin`, `margin-top`, `margin-right`, `margin-bottom`, `margin-left` | 1–4 значения, `auto` центрирует |
| `padding`, `padding-top`, `padding-right`, `padding-bottom`, `padding-left` | 1–4 значения |
| `box-sizing` | `border-box` по умолчанию (не как в браузере), `content-box` |
| `flex-direction`, `flex-wrap`, `flex-flow` | `row`, `column`, `*-reverse`; `nowrap`, `wrap` |
| `flex`, `flex-grow`, `flex-shrink`, `flex-basis`, `order` | как в CSS |
| `align-items`, `align-self`, `justify-content` | `flex-start`, `flex-end`, `center`, `stretch`, `baseline`, `space-between`, `space-around`, `space-evenly` |
| `align-content` | только у `flex-wrap: wrap`: `normal` и `stretch` растягивают строки на всю высоту; остальные значения читаются и без эффекта |
| `gap`, `row-gap`, `column-gap` | flex и grid |
| `grid-template-columns`, `grid-template-rows` | длины, `fr`, `auto`, `repeat(N, …)` |
| `grid-column` | `N`, `span N`, `N / M`, `N / span M` |
| `overflow`, `overflow-x`, `overflow-y` | `visible`, `hidden`, `clip` (то же, что `hidden`: режет, полосы нет), `auto`, `scroll`: колесо и ползунок, ползунок тянется мышью, клик по дорожке переносит его под курсор. `auto` — тонкая полоса поверх правого края содержимого; `scroll` с `padding-right` — полоса с дорожкой в этом поле, своя колонка, содержимое на неё не заходит (`padding-right: 10u` — обычная ширина) |
| `z-index` | порядок рисования среди соседей |

**Рисование**

| Свойство | Значения и замечания |
|---|---|
| `background`, `background-color` | цвет; в сокращении также картинка, повтор, позиция и размер: `background: #123 url(a.png) no-repeat center / cover`. Первый слой из списка через запятую, остальные пропускаются с предупреждением (несколько градиентов пишите в `background-image`, там рисуются все слои). Сокращение сбрасывает `background-size/position/repeat` |
| `border`, `border-width`, `border-color`, `border-style`, `border-top`, `border-right`, `border-bottom`, `border-left` | сплошная линия; `dashed` (штрихи) и `dotted` (точки) рисуются, один стиль на все четыре стороны (последняя запись со стилем главнее), остальные (`double`, `groove`…) как сплошная. У скруглённого блока стороны с разной толщиной или цветом (`border-left: 3px solid …` при прозрачных остальных) рисуются каждая сама, угол делится по диагонали |
| `border-top-width`, `border-right-width`, `border-bottom-width`, `border-left-width` | ширина рамки — целое число пикселей экрана (не меньше 1), как её рисуют: потомок вплотную к краю рамки (уголок, вкладка на линии) стыкуется без зазора в пиксель при любом масштабе |
| `border-top-color`, `border-right-color`, `border-bottom-color`, `border-left-color` | у скруглённого блока у каждой стороны свой цвет и своя ширина; угол делится по диагонали от внешнего угла к внутреннему (как в браузере), стык с мягким краем в 1 px. Сторона без ширины или с прозрачным цветом не рисуется (полоска слева у скруглённой кнопки: `border-left: 3u solid #c33`). `dashed`/`dotted`: штрихи по прямым участкам, углы сплошные |
| `border-radius`, `border-top-left-radius`, `border-top-right-radius`, `border-bottom-right-radius`, `border-bottom-left-radius` | как в CSS: 1-4 значения (порядок TL TR BR BL) и эллипс через `/`: `10px 20px / 5px`; у longhand одно значение (круг) или два (по горизонтали, по вертикали). Единицы `px`, `u`, `em`, `%` (`%` от ширины для горизонтального радиуса и от высоты для вертикального, как в CSS: `50%` у неквадратного блока даёт эллипс, раньше был круг по меньшей стороне). Если радиусы двух соседних углов не умещаются в сторону, все радиусы уменьшаются в одно и то же число раз (`999px` у блока 40x20 даёт 10). Каждый угол рисуется своим радиусом у фона и рамки. Края скруглённых блоков, колец и углов — аналитическое покрытие: один линейный переход в 1 px, тонкие кольца 1–2 px чуть подняты (`Core/Coverage.cs`). Маски с дробным радиусом пока нет: радиус округляется до целых px (`Core/Corners.cs`). `overflow` режет по прямоугольнику, не по скруглению: дети, заходящие в угол скруглённого блока, видны в квадратном углу (скруглённая обрезка не включена, см. `PERF.md`, «Скругление по overflow»). Картинка в скруглённой карточке — то же ограничение. `box-shadow` и контур берут один радиус: наибольший из меньших полуосей углов (у разных углов тень и контур округлены по самому большому, у эллипса по меньшей оси); `linear-gradient` идёт по каждому углу отдельно. Вид в игре глазами не проверен |
| `opacity`, `visibility` | `visibility: hidden` оставляет место |
| `scrollbar-color`, `scrollbar-width` | цвет ползунка; `thin`, `none` |
| `accent-color`, `caret-color` | полоса `progress`, флажок; каретка поля |
| `cursor` | наследуется; список через запятую берёт первое известное слово (`url()` не рисуется). У игры семь курсоров: `pointer`, `grab` — рука; `text`, `vertical-text` — `IBeam` (поля ввода получают его из таблицы по умолчанию); `move`, `all-scroll`, `*-resize` — стрелки `Move` (ближайший); `grabbing` — закрытая рука; `wait` — песочные часы; `progress` — курсор с часами. Остальное (`auto`, `default`, `not-allowed`, `help`, `crosshair`, `zoom-*`) — обычный курсор. У `disabled`-блока курсор не меняется. Неизвестное слово: предупреждение один раз, обычный курсор. Побеждает ближайший предок со значением (так как наследуется) |
| `outline`, `outline-width`, `outline-style`, `outline-color`, `outline-offset` | контур вокруг рамки блока, **не занимает места** (раскладка не меняется), не наследуется. `outline: <ширина> <стиль> <цвет>` в любом порядке; что не указано, сбрасывается (как в CSS: `outline: 2px red` без стиля контура не даёт; `None` и `HIDDEN` в любом регистре — тоже без контура). Ширина: длина (`px`, `u`, `em`) или `thin`/`medium`/`thick` (1/3/5 px), целое число пикселей экрана, не меньше 1. `outline-offset` — длина, может быть отрицательной (контур внутрь рамки); цвет по умолчанию `currentcolor`. Рисуется **только сплошной**: `dashed`, `dotted` и прочие стили рисуются сплошной линией, с предупреждением один раз. Контур идёт снаружи от рамки (на `outline-offset + ширину`), поверх содержимого блока, **не обрезается собственным `overflow`** блока, но обрезается `overflow` предков. У скруглённого блока контур скруглён (радиус блока плюс отступ и ширина; круглыми углами, как рамка; у блока без скругления углы прямые). Соседний блок, нарисованный позже, может закрыть контур (в браузере контур всегда сверху всего контекста наложения). Это даёт `:focus { outline: 2px solid ...; outline-offset: 2px }` для полей и кнопок; внутри `scale` контур растёт вместе с блоком |
| `pointer-events` | `none` — блок прозрачен для мыши |
| `translate` | `X Y` или `X`: сдвиг при рисовании, раскладка не меняется (блок и всё внутри едут вместе, зона мыши тоже) |
| `scale` | одно положительное число (по умолчанию `1`, не наследуется): блок и всё внутри рисуются в N раз крупнее или мельче, раскладка не меняется, как у `translate`. Центр масштаба — левый верхний угол рамки самого блока **после** его `translate` (точка p внутри блока рисуется в `угол + translate + N·(p − угол)`); вложенные `scale` перемножаются, потомки блока едут вместе с ним, мышь, обрезка `overflow` и текст согласованы с картинкой (текст берёт шрифт нужного размера и остаётся чётким). | `transition` | `свойство время [плавность] [задержка]`, список через запятую; плавное изменение при смене стиля (наведение, класс, `data-class`). См. «Анимации» |
| `animation` | `имя время [плавность] [задержка] [повторы|infinite] [направление] [fill]`; кадры берутся из `@keyframes`. См. «Анимации» |
| `transition-property`, `transition-duration`, `transition-timing-function`, `transition-delay` | отдельные части `transition`; списки через запятую повторяются, если короче |
| `animation-name`, `animation-duration`, `animation-timing-function`, `animation-delay`, `animation-iteration-count`, `animation-direction`, `animation-fill-mode` | отдельные части `animation`; например `animation-delay` для лесенки в списке: `.row:nth-child(2) { animation-delay: 0.05s }` |
| `layout-fps` | `auto` (по умолчанию: общее значение `BaroUi.LayoutFps`, 30, меняется `baroui anim fps N`), число (раз в секунду, не меньше 1) или `max` (каждый кадр): как часто пересчитывается раскладка, пока меняется длина (`width`, `height`, поля, отступы). Прозрачность, цвета, `translate` и `scale` от неё не зависят и плавны всегда |

**Внутри блока со `scale`**

Работает: фон, рамки, скругления, текст (чёткий, любой размер до 160 px на экране, дальше растягивается), кнопки, флажки, ползунки `range`, поля ввода (каретка и выделение мышью), `textarea` (мышь, выделение, полосы), `title`-подсказка, наведение, `:active` и клик на любом элементе, `overflow: hidden` и прокручиваемые блоки (колесо, ползунок полосы мышью), `<item>`, `<progress>`, `<canvas>` (обратный вызов рисует в тех же пикселях, что и без масштаба, но результат масштабируется вместе с блоком; мышь `SetCanvasMouse` отдаёт позиции в этих же пикселях).

Не поддерживается внутри блока со `scale` (то, что не сделано, не притворяется рабочим):
- ячейки инвентаря `<slot>`: игра рисует их сама по экранному прямоугольнику, они не рисуются, в журнал пишется предупреждение один раз на строку шаблона;
- выпадающий список `<select>`: строки списка рисуются без масштаба, у правильного места: список открывается поверх всего на экране под (или над) полем, по его прямоугольнику с учётом `translate`, прокрутки и `scale` всех предков, шириной и высотой строки, как у поля на экране (то есть в масштабе поля), но шрифт в строках обычного размера;
- `<dialog>` (модальное окно) открывается поверх экрана без масштаба и без `translate` и прокрутки предков, что бы ни стояло у его предков; в журнал пишется предупреждение один раз на строку шаблона;
- курсивный `font-style: italic` у шрифта без своего курсива (JetBrains Mono, Caveat) рисуется обычным шрифтом размера CSS и растягивается матрицей (нечётко); у `'PT Serif'` курсив настоящий и чёткий;
- обратный вызов `<canvas>`, который сам читает мышь (`PlayerInput`) или перезапускает пакет, считает в экранных пикселях: берите `SetCanvasMouse`;
- `UiWindow.BoxOf` отдаёт прямоугольник раскладки (без `translate`, FLIP-сдвига, прокрутки и `scale`): место на экране даёт `ScreenRect(element)`: оно учитывает `translate` (из CSS или числом `SetTranslate`) и сдвиг анимации раскладки самого элемента и каждого предка, прокрутку областей вокруг и вложенные `scale` в том же порядке, как рисует `Painter` (`Core/ScreenMap.cs`); так же считаются каретка и прямоугольник IME поля, подсказка `title`, список `<select>`, полоса прокрутки и зона мыши поля `range`;

## Скругление детей по overflow

Блок с `overflow: hidden`, `auto` или `scroll` по обеим осям и с `border-radius` режет детей по скруглению, если хотя бы один ребёнок заходит в угол: фон, рамки, картинки, текст, прокрутка, липкие строки. Ничего в разметке не нужно. Блоки без захода в угол и блоки с обрезкой по одной оси рисуются как раньше, прямоугольником.

- Содержимое берётся из раскладки этого же кадра (проход идёт после обновления окна).
- Не больше 32 таких блоков на окно за кадр; остальные режутся прямоугольником, в журнал пишется число.
- Блок внутри `scale` режется прямоугольником; текст самого блока (не детей) тоже.
- Нажатия и наведение работают по раскладке, как всегда.
- Не проверено в игре; ui_host показывает (`docs/ui/PERF.md`).

## Анимации

Движок считает анимации сам, на каждом кадре. Ничего не нужно вызывать из кода: страница пишет CSS, как в браузере.

**Что можно менять плавно.** Только то, что движок умеет интерполировать:
- прозрачность: `opacity`;
- цвета: `color`, `background-color`, `border-*-color`, `outline-color`, `text-decoration-color` (из `transparent` цвет не темнеет, берётся цвет цели; `currentcolor` — цвет самого элемента);
- тень: `box-shadow` — сдвиг, размытие, разброс и цвет (пока тень одна, это первая из списка); `none` — тень без размера и прозрачная, так что тень появляется и уходит плавно. Цвет и геометрия идут вместе. `@keyframes` тень не берут, только `transition`;
- сдвиг: `translate`, он рисуется без пересчёта раскладки, дёшево;
- масштаб: `scale` (число, как `opacity`), тоже без пересчёта раскладки: `transition: scale 0.2s ease-out`, `@keyframes` со `scale`;
- длины в `px`/`u`/`em` или в `%` (оба конца одной единицы): `width`, `height`, `min-*`, `max-*`, `margin-*`, `padding-*`, `border-*-width`, `top`, `right`, `bottom`, `left`, `row-gap`, `column-gap`. Они двигают раскладку, и пока длится движение, раскладка этого блока пересчитывается. Чтобы это было дёшево, длины берутся не каждый кадр, а по сетке времени: `layout-fps` (по умолчанию 30 раз в секунду, свой на блок или общий `baroui anim fps N`), а раскладка запускается только когда значение действительно сдвинулось. Поэтому `steps(n)` тоже работает как частота: n шагов, n пересчётов. Всё равно держите такие анимации на небольших блоках и коротких (до 0,3 с), для остального берите `opacity` и `translate`.
Если один из концов не число (`auto`, `none`) или единицы разные, значение меняется сразу.

**`transition`.** `transition: opacity 0.15s ease-out, background-color 0.15s; ` или `transition: all 0.2s`. Плавности: `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, `cubic-bezier(x1, y1, x2, y2)`, `steps(n)`. Стиль, в который переходит блок, решает, какой переход играет (как в CSS): чтобы и наведение, и уход курсора были плавными, пишите `transition` в обычном правиле блока, не только в `:hover`. Новый блок появляется сразу в готовом виде, без перехода. Переход, прерванный на середине, начинается с того значения, где остановился.

**`transition: layout`: плавная раскладка без пересчёта по кадрам.** Когда блок раскрывается, сворачивается или список сдвигает строки, дёшево не пересчитать раскладку десять раз, а посчитать её один раз сразу в конечных размерах, а картинку проиграть от старого вида к новому. Так и работает `layout`:
```css
.row { transition: layout 0.25s ease-out; }          /* строка плавно едет на новое место и плавно меняет размер */
.panel { transition: layout 0.2s ease-out, opacity 0.15s; }
```
- Что анимируется: положение блока относительно его родителя (блок и всё внутри едут вместе) и размер (ширина и высота: блок рисуется в промежуточном размере, содержимое остаётся в конечной раскладке и обрезается рамкой, как при раскрытии шторки; текст не перестраивается по ходу).
- Включите `layout` у блока, который меняет размер, и у его соседей, которые от этого сдвигаются (обычно у всех строк списка). Блок без `layout` перескакивает сразу.
- Кадр стоит как обычная отрисовка: пересчёта раскладки нет ни на каком FPS, `layout-fps` тут не нужен. Обрезка по рамке включается только у блоков, чей размер сейчас меняется.
- Прерванное движение продолжается с того места, где блок нарисован сейчас, а не с начала. Раскладка, которая блок не сдвинула, движение не перезапускает.
- Новые блоки не анимируются (для появления берите `opacity` и `@keyframes`). Первая раскладка окна и смена размера экрана тоже без перехода.
- `transition: all` блоки раскладки не включает, `layout` пишется явно. Не вешайте его на строки длинного прокручиваемого списка с `data-for` (виртуального): при прокрутке строки пересоздаются и могут ехать на новое место.
- В браузерном предпросмотре движение не видно (браузер не знает `layout`): блоки перескакивают сразу.

**`animation` и `@keyframes`.**
```css
@keyframes rise { from { opacity: 0; translate: 0 12u } to { opacity: 1; translate: 0 0 } }
.panel { animation: rise 0.25s ease-out both; }
```
Остановки: `from`, `to`, `NN%`; сокращения вроде `margin` в них раскрываются, `var()` не подставляется. Если `from` или `to` пропущены, берётся значение из обычного стиля блока. Повторы: число или `infinite`; направление: `normal`, `reverse`, `alternate`, `alternate-reverse`; `fill`: `none`, `forwards`, `backwards`, `both`. Анимация стартует, когда блок появился (страница открылась, пришла строка списка, `data-if` включил блок), и начинается заново, если у блока сменилось значение `animation`. Скрытый `data-if` блок при показе стартует снова.

**Печатная машинка.** `typewriter: 60` у блока с текстом показывает его по 60 знаков в секунду. Окно сообщает `IsTyping`; по клавише подтверждения хозяин страницы зовёт `SkipTyping`, чтобы показать всё сразу.

**Чего нет и что учесть.**
- Цвет текста наследуют потомки от обычного стиля родителя: меняйте `color` у блока, которому текст принадлежит, а не у обёртки.
- `translate` и раскладочный переход двигают картинку и зону мыши блока, но не ячейки инвентаря (`slot`) и предметы внутри: их место игра берёт из раскладки. Не анимируйте блоки, в которых лежат ячейки.
- Время идёт по часам игры (`Timing.TotalTime`), на паузе мира анимации продолжаются, они привязаны к кадру окна.

## Теги

- Блоки: `div p section header footer nav main aside ul ol li h1–h4 table tr td th form dialog`; строчные: `span b strong i em a label`. `tr` — flex-строка, `td`/`th` делят её поровну.
- `head title meta link style script option template` не рисуются. Стили — `<link rel="stylesheet" href="x.css">` (файл рядом со страницей) и `<style>`.
- **Поля** (рисует движок, не игра):
  - `<input>`: `type` = `text`, `search`, `password` (звёздочки), `number` (`min`, `max`, `step`; стрелки вверх и вниз; колесо над полем меняет значение и с фокусом, и без него: с фокусом как стрелка, без фокуса сразу, с `oninput` и `onchange`; на пределе колесо листает страницу), `checkbox`, `range`. Атрибуты `placeholder`, `maxlength`, `disabled`, `autofocus`.
  - `<input type="radio" name="группа" value="v">`: радио с одним `name` в окне — одна группа, отмечена одна (без `name` — группа из одного). Клик, Enter или Space отмечают и снимают остальных; `onchange` приходит только новому отмеченному. `data-model` достаточно поставить на одно радио группы: отмечено то радио группы, чьё `value` (без него `on`) равно значению в модели (сравнение по тексту, `3` и `"3"` совпадают), и радио без своего `data-model` тоже следуют за моделью; нажатие на любое радио группы пишет его `value` в модель. `onchange` приходит после удачной записи в модель (если запись не удалась, в журнале предупреждение и `onchange` нет). Исключение в обработчике, вызванное клавишей (стрелка по радио, Enter, `oninput` при печати), записывается в журнал и закрывает окно, как при ошибке в обработчике мыши. Фокус: Tab встаёт на отмеченное радио группы (пока нет отмеченного — на первое), стрелки вверх/влево и вниз/вправо переходят к соседу и отмечают его. `:checked` работает; по умолчанию радио — круг в 1em (`input[type=radio] { width: 1em; height: 1em; padding: 0; border-radius: 50%; cursor: pointer }`, отмеченное с фоном `#1d3a3f`), страница может переопределить; точка внутри рисуется цветом `accent-color`.
  - `<input type="range">` (ползунок): `min` (0), `max` (100), `step` (1; `any` — без сетки), `value` (без него середина), `data-model`, `oninput` (на каждое движение), `onchange` (по отпусканию мыши и на каждую клавишу). Мышь: нажатие на дорожку ставит движок под курсор, дальше он идёт за мышью, клавиатуру игре не отдаёт. Tab: стрелки — шаг, PageUp/PageDown — десять шагов, Home/End — края. Значение встаёт на сетку шага от `min`; `max` вне сетки недостижим (как в HTML). Рисует движок: дорожка цветом текста (22 % прозрачности), часть до движка и сам круглый движок цветом `accent-color`; размер задаёт `height` (движок 4/5 высоты, дорожка 3/10), цвет фона и рамка по умолчанию прозрачные и нулевые. Мышь над ним подсвечивает движок, фокус с клавиатуры — кольцо. Колесо ползунок не двигает (оно листает страницу).
  - `<select>` с `<option value>`; `disabled` у варианта. Своё выпадающее окно на 8 строк, колесо и стрелки.
  - `<button>`, `<progress value max>` (без `value` — бегущая полоса).
  - Клавиши: Tab — следующее поле, Enter — кнопка `data-default` (если у поля есть `onenter`, Enter вызывает его, а кнопку не нажимает), Esc — закрыть список, затем диалог, затем окно. `accesskey="o"` — Alt+O. `title` — подсказка игры через 0,4 с.
- **Игровые теги**:
  - `<item prefab="oxygentank" count="3">` — иконка предмета игры;
  - `<canvas id="scope">` — рисует C#: `Window.SetCanvas("scope", (sb, rect) => …)` (с мышью — `Window.SetCanvasMouse`, с картинками из файлов — `Window.Images`, см. «Ввод»);
  - `<textarea id="code" data-lang="xml">` — многострочный редактор кода с подсветкой XML/Lua/C#, тысячи строк (см. «Ввод»);
  - `<slot inventory="in" index="0">` — настоящая ячейка инвентаря игры: `Window.SetInventory("in", inventory)`. Перетаскивание, подсказки, стопки и сеть работают как в игре, пока игра сама обновляет этот инвентарь (его предмет выбран). Размер задаёт CSS, полоску состояния игра рисует над ячейкой — оставьте сверху место. Ячейка, прокрученная за край или накрытая окном `dialog`, мышь не берёт. После `SetInventory(name, null)` или закрытия окна ячейки возвращаются игре;
  - Рамка ячейки — свойство `-bbe-slot-frame` у `<slot>` (не наследуется): `game` (по умолчанию, рамка игры), `none` (рамки нет: видны `background`, `border`, `border-radius` самого `<slot>`, игра рисует только предмет, полоску состояния и число в стопке), `url("рамка.png")` (своя картинка, растягивается на ячейку; путь как у картинок). Картинка не нашлась — рамка игры и одна строка в журнале. В игре не проверено.
  - `<dialog id>` — модальное окно: `showModal('id')`, `closeDialog()`; без `top/left/right/bottom` — по центру, с ними — от ближайшего `position: relative` предка; `closedby="any"` — закрывается нажатием мимо окна (панель фильтров, всплывающее меню);
- `<img src="файл.png" alt="…">`: рисует картинку в содержимом блока по `object-fit`. Размер задаёт CSS (`width`, `height`, `u`); если CSS оставил сторону `auto`, берётся размер картинки в пикселях файла (как `background-size: auto`): обе стороны — как в файле; одна сторона задана длиной (`px`, `u`, `em`) — вторая по пропорциям картинки. Атрибутов `width`/`height` нет. Нет файла — блок 0 x 0 и ничего не видно. Путь, как у `background-image` (от папки страницы). Вместо ненайденной картинки рисуется `alt` одной строкой. `src="sprite(item:oxygentank)"` показывает спрайт игры.
- `<curve>`, `<chart>`, `<gauge>` — блоки (`display: block` по умолчанию; размер задаёт CSS, см. «Графики»).
- Нет: `iframe`, `input type=color`.

## Ввод: мышь на холсте, редактор кода, картинки, файлы

Этап D: примитивы для окон, которым мало полей и кнопок (менеджер модов: карта сборки, окна кода, спрайты модов). Всё в `own/BaroUI`; проверки: `tools/ui_test` (группы «canvas mouse», «code editor», «pictures and files»), в игре страница `UI/inputs.html` (`baroui open inputs`; самотест `Api/SelfTestInput.cs`).

### Мышь на элементах: `data-mouse`, `SetMouse`

Для карточек, карт, всего, что тянут и на что нажимают. Элемент с `data-mouse="имя"` получает события мыши; обработчик хозяин ставит по имени: `Window.SetMouse("card", e => { … })` (вариант с `Action<UiMouseEvent>` отвечает `true` всегда), `Window.ClearMouse("card")` снимает (захват, который он держал, кончается `Cancel`). `data-mouse-events="down up click dblclick contextmenu wheel enter leave move hover"` — какие события нужны; по умолчанию все, кроме `move` и `hover`.

- **Поля события** `UiMouseEvent`: `Kind`, `Button`, `Held`, `X`/`Y` (экран), `LocalX`/`LocalY` (в содержимом `Current`, в его пикселях), `Width`/`Height`, `Target` (самый глубокий элемент под указателем), `Under` (см. ниже), `Current` (чей обработчик зовут), `Up("data-node")` — ближайший предок с атрибутом, `Data("part")` — значение `data-part` ближайшего элемента от `Target`, `Captured`, `Inside`, `Dragged`, `ClickCount`, `StartX`/`StartY`, `Wheel`, `Ctrl`/`Shift`/`Alt`, `Related` (для `Enter`/`Leave`), `Capture()`.
- **Всплытие** идёт от самого глубокого элемента вверх по предкам с `data-mouse`. `true` останавливает его, а на `Down` ещё и берёт захват: `Move`, `Up`, `Wheel` идут держателю везде, пока не отпущены все его кнопки; `Esc` отменяет захват (`Cancel`), другое на этом нажатии не закрывается. `Enter` и `Leave` не всплывают: каждый вошедший элемент получает своё.
- **`Click`** (и `DoubleClick`, `ContextMenu` для правой) приходит, когда кнопка отпущена на элементе (внутри него), где была нажата. В отличие от браузера, **после перетаскивания дальше 4 px `Click` не приходит**: сдвинутая карточка не «нажата».
- Холст с `SetCanvasMouse` забирает свои нажатия, движения и колесо себе: предки с `data-mouse` их не получают. `Enter` и `Leave` предки получают и над холстом (указатель вошёл в предка или вышел из него). Холст и держатель `data-mouse` вместе мышь не держат.
- Пока мышь захвачена (перетаскивание), `:hover` и подсказки `title` стоят на месте: карточка, которую несут над панелью, не подсвечивает её кнопки.
- Старый `onclick` не тронут и не дублируется: `Click` роутера — отдельное событие. Правило «после сдвига дальше 4 px щелчка нет» к `onclick` **не** относится: элемент с `onclick`, отпущенный там же, где нажат, его получит и после перетаскивания.
- `Under` — элемент под указателем, пока мышь держит захват или несёт перетаскивание (`DragDrop`): держатель захвата или призрак перетаскиваемого элемента и всё внутри них не учитываются (проверка попадания идёт с ними, сдвинутыми далеко, потом возвращаются на место); `pointer-events: none` пропускается, как при обычном нажатии. Вне захвата и перетаскивания `Under` = null. `Target` не меняется: держатель захвата, или элемент под призраком.
- Не сделано: сахар `onmousedown="…"` в разметке.

### Фокус, Tab и клавиши на блоках: `tabindex`, `data-keys`, `SetKeys`

- **Фокус по клику.** Нажатие на элемент (или на то, что внутри него) с явным `tabindex` (любым числом, и `-1`) отдаёт ему клавиатуру; персонаж при этом замирает, как у текстового поля. Кнопки, флажки, радио, ползунки и списки без `tabindex` по клику фокус **не берут**, и это сделано нарочно: клик по кнопке не должен останавливать персонажа; они берут клавиатуру только с Tab. Явный `tabindex` на них включает фокус и по клику. Кнопка внутри блока с `tabindex` по клику отдаёт фокус блоку (ближайшему предку с `tabindex`), и клавиши идут блоку.
- **Порядок Tab** как в HTML: сначала элементы с положительным `tabindex` по возрастанию числа (при равных — по порядку документа), потом `tabindex="0"` и обычные поля, кнопки и т.п. в порядке документа. `tabindex="-1"` фокусируется кликом и из кода (`focus(id)`), но Tab его пропускает. Shift+Tab идёт назад, по кругу. Список стопов собирается заново на каждое нажатие (смена `tabindex` без раскладки заметна сразу), и стоп с отрицательным `tabindex` пропускается всегда. **Пока открыто всплывающее окно** (`data-popup`), Tab и Shift+Tab ходят по стопам внутри него по кругу, как в меню, и на страницу за ним не уходят; закрывают его Esc, выбор пункта или щелчок мимо.
- **Клавиши блоку.** `data-keys="Enter Space Escape ArrowUp ArrowDown ArrowLeft ArrowRight Delete Backspace Home End PageUp PageDown Tab"` (нужное подмножество; имена как в перечислении `UiKey`, без учёта регистра: `Enter Space Escape ArrowUp ArrowDown ArrowLeft ArrowRight Delete Backspace Home End PageUp PageDown Tab`; псевдонимы: `Esc`, `Up`, `Down`, `Left`, `Right`, `Del`, `Return` (то же, что Enter), `Back` (то же, что Backspace)) и `data-key-name="имя"`; обработчик: `Window.SetKeys("имя", e => { ... return true; })` (вариант с `Action<UiKeyEvent>` отвечает `true` всегда), `Window.ClearKeys("имя")`. Событие `UiKeyEvent`: `Key` (`UiKey`), `Ctrl`, `Shift`, `Alt`, `Target` (элемент в фокусе), `Current` (чей `data-keys` сработал). Нажатие идёт от элемента в фокусе вверх по предкам, которые просили эту клавишу; `true` останавливает всплытие и **отменяет действие по умолчанию** (Space на флажке, Tab как переход фокуса, Esc как закрытие). **Клавиши правки у текстового поля** (одно- и многострочного, `<textarea>`) в `data-keys` предков не попадают: Delete, Backspace, Left, Right, Home и End всегда идут полю; в `<textarea>` ещё Enter, Up, Down, PageUp, PageDown; в числовом поле Up и Down (шаг). Остальные клавиши (Esc, Tab, Space, Enter в однострочном поле) по-прежнему идут сначала в `data-keys`.
- **Только при фокусе.** Клавиши окну приходят, пока какой-то его элемент в фокусе: так устроена игра (клавиатуру берёт один подписчик, и персонаж не должен терять управление, пока ничего не выбрано). Без фокуса блок клавиш не получит; для карты и списков дайте корню `tabindex="0"` (или `-1`).
- Esc приходит из перехвата игры (`BaroUi.PauseMenuPrefix`): его получает самое верхнее окно на экране (последнее в списке окон, то есть нарисованное поверх, среди открытых и показанных за последние 0,5 с), в нём сначала закрывается всплывающее окно или диалог, потом само окно. Меню игры открывается, только когда на экране нет открытых окон; окно, оставленное открытым там, где оно не рисуется, Esc не забирает. Отпускания клавиш (`keyup`) нет.
- Шаг назад вида: `protected override bool OnEscape()` у `BaroUiView` вызывается после всплывающего окна, списка и диалога и **до** закрытия окна (событие `Escape` окна тоже после неё). `true` — вид сам сделал шаг назад, окно остаётся; `false` — окно закрывается. Так окно с вложенными уровнями (меню, выбор, внутренний список) может сначала отдать Esc своим уровням и закрыться только на верхнем. Хуки доступны любому виду; менеджер модов может ими пользоваться, но его кода в движке нет.
- Кнопки мыши 4 (назад) и 5 (вперёд), Alt+Left и Alt+Right: верхнее окно под указателем (для Alt-стрелок — самое верхнее). Сначала ищется атрибут `onback` / `onforward` на элементе под указателем и его предках, затем на элементе в фокусе и его предках; обработчик вызывается, как `onclick`. Если его нет, вызывается `protected override bool OnBack()` / `OnForward()` вида. `true` — обработано: кнопка 4 или 5, нажатая над окном, которое её взяло, игре не передаётся на этот кадр. Кнопка над пустым местом остаётся игровой. Боковые кнопки не приходят в `data-mouse` (`UiMouseEvent`). Код: `Api/BaroUi.cs` (`NavigateByInput`), `Render/UiWindow.cs` (`Navigate`), `Core/NavRoute.cs`. В игре не проверено.
  ```html
  <div id="map" onback="backMap()" onforward="forwardMap()"> … </div>
  ```
- Модель страницы из файла: `baroui open <page>` без модели от вида берёт `UI/<page>.data.json` рядом со страницей (`Core/JsonModel.cs`, тот же читатель у `tools/ui_host --data`). Для `charts` это `charts.data.json`; `inputs.data.json` даёт `ui_host`, а в игре `inputs` открывает самотест с собственной моделью. `pseudo_demo.html` данных не читает.

### Мышь на `<canvas>`

`Window.SetCanvasMouse("pad", e => { … })` — обработчик событий мыши холста. Рисует по-прежнему `SetCanvas`; мышь можно подключить и без рисования.

| Событие `e.Kind` | Когда |
|---|---|
| `Move` | указатель двигается над холстом (первое — вход на холст); во время перетаскивания — где угодно на экране |
| `Down` / `Up` | кнопка нажата на холсте / отпущена (`e.Button`: `Left`, `Right`, `Middle`; `e.Left`, `e.Right`, `e.Middle`) |
| `Wheel` | колесо над холстом или во время перетаскивания; `e.Wheel` — щелчки, вверх положительно |
| `Leave` | указатель ушёл с холста, кнопок нет (снять подсветку) |
| `Cancel` | перетаскивание отобрано: окно закрылось, холст пропал или его накрыл диалог; `Up` не придёт |

- Поля события: `X`, `Y` — пиксели от левого верхнего угла **содержимого** холста, те же пиксели, что `Rectangle` в `SetCanvas`; во время перетаскивания выходят за `0..Width`, `0..Height`; `Width`, `Height` — размер содержимого; `Ctrl`, `Shift`, `Alt`; `Held` — кнопки, зажатые после события; `Captured`, `Inside`; `Time` — секунды.
- **Захват.** Кнопка, нажатая на холсте, пока обработчик отвечает `true`, держит мышь: `Move`, `Up`, `Wheel` идут холсту, пока не отпущены все такие кнопки, и вне холста, и вне окна. Пока идёт перетаскивание, мышь всего экрана принадлежит окну (игра под указателем не получает ни движения, ни отпускания), персонаж не управляется. Вторая кнопка, нажатая во время перетаскивания, присоединяется к нему.
- **Ответ обработчика** (`Func<CanvasMouseEvent, bool>`): для `Down` `true` — нажатие принято, начинается перетаскивание, `false` — холст его не берёт; для `Wheel` `true` — колесо использовано, `false` — страница под холстом прокручивается как обычно. Перегрузка с `Action<CanvasMouseEvent>` отвечает `true` всегда. `ClearCanvasMouse(id)` или `null` снимает обработчик (перетаскивание кончается `Cancel`).
- **Двойное нажатие считает хозяин.** `ClickCounter.Count(e)` даёт 1, 2, 3 (и снова 1) по времени (0,4 с) и месту (6 px) подряд идущих `Down` одной кнопки.
- Холст принимает мышь только в своих границах; вне их игра получает мышь как раньше. `cursor` не меняется. Клавиатуру холст не получает: клавиши карты хозяин читает сам, через `PlayerInput`.
- Ошибка в обработчике снимает его и пишет строку в журнал; окно не закрывается.

```csharp
Window.SetCanvas("map", Draw);
var clicks = new ClickCounter();
Window.SetCanvasMouse("map", e =>
{
    switch (e.Kind)
    {
        case CanvasMouseKind.Down when e.Left: if (clicks.Count(e) == 2) { Open(NodeAt(e.X, e.Y)); } else { Grab(e.X, e.Y); } return true;
        case CanvasMouseKind.Move when e.Captured: Drag(e.X, e.Y); return true;
        case CanvasMouseKind.Wheel: Zoom(e.Wheel, e.X, e.Y); return true;
    }
    return true;
});
```

### Сдвиг и масштаб числами: `SetTranslate`, `SetScale`

Для всего, что едет каждый кадр (перетаскивание карточки, панорама, зум), не пишите `style="translate: {{x}}px"`: каждое новое значение — новая строка стиля и новый разбор. Берите числа:

- `Window.SetTranslate(el, x, y)` — сдвиг в пикселях; `Window.SetScale(el, s)` — масштаб (центр — левый верхний угол блока после его `translate`, как у CSS `scale`; `0`, отрицательное и не число считаются единицей);
- `Window.ClearTranslate(el)` / `Window.ClearScale(el)` — вернуть значение из CSS;
- число **заменяет** CSS-значение этого элемента (как `element.style` в браузере), вместе с переходом и анимацией этого свойства; без перестиливания и пересчёта раскладки, зона мыши едет вместе с картинкой;
- `NaN` и бесконечность игнорируются; на копию (`Clone`) число не переносится; элемент не из страницы этого окна (убранный `data-if`) не сдвигается;
- число живёт на **элементе**: у `data-for` без `data-key` элементы идут по номеру строки, и при вставке в начало или перестановке сдвиг останется на месте, а данные уедут. Для всего, что сдвигаете числом, ставьте `data-key`. Строка виртуального списка, взятая из запаса, приходит без чисел и без `:hover`/`:focus`/`:focus-within` прежней.

Кэши стилей ограничены (два поколения: 2048 строк `style` и 8192 стилей на поколение), так что привязка в `style` больше не раздувает память без конца, но дёшево она от этого не стала: оставьте её для редких изменений.

Не меняйте `font-size` каждый кадр (`style="font-size: {{x}}px"`): каждый новый размер текста — шрифт игры, который движок держит до выгрузки модов (около 8 МиБ). Для плавного увеличения есть `scale`: шрифты под масштаб ограничены и выгружаются.

### Всплывающее окно и контекстное меню: `data-popup`, `data-contextmenu`, `ShowPopup`

```html
<div class="menu" data-popup id="cardMenu" style="width: 160px">
  <button onclick="rename()">Переименовать</button>
  <button data-item onclick="remove()">Удалить</button>
  <button data-keep-open onclick="pin()">Закрепить</button>
</div>
<div class="card" data-contextmenu="cardMenu">…</div>
```

- Блок с `data-popup` скрыт, пока его не показали (правило движка со `!important`: `#cardMenu { display: flex }` его не откроет); открытый лежит `position: absolute` над страницей. Задайте ему ширину: ширина по содержимому считается от родителя.
- `Window.ShowPopup(id, screenX, screenY, anchor = null)` — у точки (контекстное меню; `anchor` — элемент, для которого открыли, его отдаёт `Window.PopupAnchor`, например карточка); `Window.ShowPopup(id, anchor, "below")` — под, над (`above`), справа (`right`), слева (`left`) от `ScreenRect(anchor)`. Не помещается — переворот на другую сторону, потом сдвиг внутрь экрана (у точки: влево/вверх от курсора). Расчёт — `Core/Popup.cs`, `PopupPlace`.
- `Window.ClosePopup(id = null)`, `Window.IsPopupOpen(id)`, событие `Window.PopupClosed(popup, reason)` и атрибут `onclose` у самого блока. Причины: `Outside` (нажатие мимо), `Escape`, `Chosen` (выбран пункт), `Code` (`ClosePopup`, окно удалили `data-if`, открыто модальное окно), `Replaced` (открыли другое).
- Одно всплывающее окно за раз: открытие второго закрывает первое. Открытое повторно просто переезжает. Вложенных подменю нет.
- Нажатие мимо: левая кнопка закрывает окно и **не доходит** до страницы (как у родных меню: ни клика по тому, что под ним, ни смены фокуса); правая закрывает и проходит дальше, поэтому на другой карточке сразу откроется её меню. Нажатие в сам блок работает как обычно.
- Пункт — `button`, `a` с `onclick`, элемент с `data-item` или любой с `onclick` внутри окна: после его `onclick` окно закрывается (`Chosen`). `data-keep-open` на пункте или на предке оставляет открытым. Клик по полю и тексту окна его не закрывает.
- Esc: сначала отмена захвата мыши (перетаскивание), потом всплывающее окно, потом данные `data-keys`, список `select`, модальное окно, окно страницы. Если внутри открытого меню раскрыт `<select>`, Esc закрывает меню целиком, вместе со списком. Если обработчик закрыл окно, цепочка Esc на этом заканчивается.
- Клавиши меню: стрелки вверх и вниз, Home и End переходят по пунктам (кнопки, `data-item`, ссылки с `onclick`) там, где в фокусе пункт; у поля ввода, `<select>`, ползунка, радио и многострочного поля внутри меню эти клавиши остаются их собственными. Tab в открытом меню не выходит из него (см. «Порядок Tab»). Пункт, чей `onclick` закрыл меню и открыл его снова, оставляет новое меню открытым.
- Клавиатура: при открытии фокус получает первый пункт (`button`, `a` с `onclick`, `data-item`; `data-item` берёт фокус и без `tabindex`); Вверх/Вниз/Home/End ходят по пунктам по кругу, Enter и Пробел нажимают пункт (как клик, окно закроется по правилу выше).
- `data-contextmenu="id"` на элементе (или предке): правая кнопка, нажатая и отпущенная на нём (сдвиг не больше `PointerRouter.DragThreshold`), открывает окно `id` у курсора. Если обработчик `SetMouse` вернул `true` на `ContextMenu`, меню не открывается: обработчик забрал событие и открывает своё сам, `ShowPopup(id, e.X, e.Y, card)`. Так же меню не открывается, если правое нажатие взял держатель захвата (`true` на `Down` или захват, который уже держится), или оно пришлось на холст с обработчиком мыши (`PointerRouter.RightTaken`): владелец открывает своё меню сам.
- Слой: окно рисуется поверх страницы и поверх модальных `<dialog>` (так меню внутри диалога видно); открытие `<dialog>` кодом закрывает всплывающее окно. Рисуется тем же путём, что `<dialog>`: из нулевого смещения, без масштаба и прокрутки предков, поэтому внутри блока со `scale` оно открывается обычного размера.

### Перетаскивание между блоками: `data-drag`, `data-drop`, `SetDrop`
Карточку берут левой кнопкой и бросают на другой блок страницы. Без клона: двигается сам элемент.
```html
<div class="card" data-drag="item" data-drag-value="{{c.id}}" data-drag-name="cards">...</div>
<div class="slot" data-drop="item note" data-drop-name="slots"></div>
```
```csharp
window.SetDrop("slots", e =>
{
    // e.Phase: Enter, Over, Leave, Drop; e.Kind, e.Value (data-drag-value), e.Source (карточка), e.Target (блок с data-drop),
    // e.X/e.Y (экран), e.LocalX/e.LocalY (точка в блоке-приёмнике), e.Ctrl/e.Shift/e.Alt
    if (e.Phase != UiDropPhase.Drop) { return true; }
    return Put(e.Target.GetAttribute("data-slot"), e.Value);      // true: принято
});
window.SetDrop("cards", e => { if (e.Phase == UiDropPhase.Cancel) { Reset(e.Source); } return true; });   // источник узнаёт об отмене
```
- Один обработчик на имя, как у `SetMouse` и `SetKeys`: событие несёт и источник, и приёмник, значит один обработчик обслуживает весь список; отдельного обработчика на каждый элемент не нужно. Имя приёмника: `data-drop-name`, имя источника: `data-drag-name` (получает только `Cancel`).
- `data-drop` перечисляет виды через пробел, `*` берёт любой. Приёмник под указателем ищется вверх по предкам: вложенный блок внутри приёмника тоже считается им. Блок, который не берёт вид, пропускается (смотрится внешний).
- Начало: нажатие на элемент с `data-drag` (или внутри него) и сдвиг дальше 4 px. Нажатие на `input`, `textarea`, `select`, `slot` и на отключённый элемент перетаскивания не начинает; если нажатие взял обработчик `data-mouse` (вернул `true`) или полоса прокрутки, перетаскивания тоже нет.
- Состояния для CSS: `:dragging` у источника, `:drag-over` у приёмника под указателем, только если он берёт вид. Оба проходят через индекс состояний (как `:hover`), соседские `+ ~` и потомки работают. Пример: `.slot:drag-over { border-color: #40c8be }  .card:dragging { opacity: .7; z-index: 50 }`.
- Призрак: сам источник, сдвинутый числовым `translate` за указателем (`SetTranslate`). Его CSS-`translate` на время жеста заменяется, потом возвращается к CSS. Предки с `overflow: hidden` его обрежут, поднимайте `z-index` в `:dragging`. Внутри масштабированного блока смещение указателя делится на масштаб блоков вокруг источника (у призрака тот же шаг, что у указателя), и собственный CSS-`translate` карточки остаётся под ним (`DragDrop.GhostShift`). Вид (`data-drag`) и значение (`data-drag-value`) запоминаются при начале жеста: все события, включая `Cancel`, несут их, а не то, что на элементе к концу. Приёмник, пропавший или закрытый диалогом посреди жеста, получает `Leave` и теряет `:drag-over`. Если обработчик в кадре отпускания закрыл окно или отменил жест, `Drop` не приходит.
- Что под указателем: элемент без источника (на время одной проверки источник уходит за экран, ничего не рисуется между). Под курсором всегда настоящий элемент, а не призрак. `:hover` на время перетаскивания замирает, подсвечивается `:drag-over`.
- Конец: отпускание над приёмником, берущим вид, шлёт `Drop`; `true` принимает. Любой другой исход (отпустили мимо, `false`, Esc, источник пропал, диалог закрыл окно) шлёт `Leave` (если был над приёмником) и `Cancel` источнику. Приёмник без обработчика отказывает. Esc отменяет перетаскивание, и только его.
- `onclick` элемента после перетаскивания не вызывается, даже если кнопку отпустили позже Esc.
- Исключение в обработчике снимает его и считается отказом. Ответ на `Enter`, `Over`, `Leave` и `Cancel` игнорируется.
- Не смешивать с `<slot>` игры (предметы): тот жест ведёт игра. Бросок предмета игры на блок HTML не сделан.

### Редактор кода: `<textarea>`

```html
<textarea id="code" data-lang="xml" data-model="text" oninput="edited()" onsave="save()" tabsize="4" placeholder="Пусто"></textarea>
```

Многострочный редактор, рисует движок: строки, каретка, выделение, прокрутка, подсветка. Текст — `value`: содержимое тега (как в HTML, первый перенос не считается), атрибут `value`, `data-model` (в обе стороны; запись в модель — не чаще раза за кадр) или `Window.GetCodeEdit("code").SetText(…)`.

| Атрибут | Что делает |
|---|---|
| `data-lang` | `xml`, `lua`, `cs` (или имя файла: `x.xml`) — подсветка; без него текст без цветов |
| `data-model`, `value`, `placeholder`, `readonly`, `disabled` | как у `input` |
| `tabsize` | ширина табуляции в знаках (4) |
| `data-tabs="tab"` | Tab пишет знак табуляции, а не пробелы |
| `data-autoindent="off"` | Enter не копирует отступ |
| `data-gutter="off"` | без номеров строк |
| `oninput` | после правки (один вызов на кадр, как бы ни было нажато клавиш) |
| `onchange` | при уходе из редактора, если текст изменился с момента входа |
| `onsave` | Ctrl+S |

- **Размер и вид.** UA-лист: `30em × 12em`, рамка, `overflow: hidden` (прокрутка своя). Шрифт — **моноширинный** (по умолчанию `font-family: mono`): ширина знака измеряется один раз, по ней считаются колонки, каретка и мышь. Высота строки — `line-height` (число или длина). Переноса строк нет: длинная строка прокручивается вбок (Shift+колесо, полоса снизу).
- **Цвета** — пользовательские свойства, наследуются: `--code-keyword`, `--code-type`, `--code-constant`, `--code-string`, `--code-number`, `--code-comment`, `--code-punct`, `--code-tag`, `--code-attr`, `--code-entity`, `--code-directive` (подсветка), `--code-gutter` (номера строк), `--code-line` (строка с кареткой), `--code-selection`. Простой текст — `color`, каретка — `caret-color`.
- **Клавиши.** Стрелки, Ctrl+стрелки (слово), Home (первый знак строки, ещё раз — начало), End, Ctrl+Home/End, PageUp/PageDown, Shift со всем этим — выделение; Tab — до следующего стопа (с выделением: отступ строкам, Shift+Tab — убрать); Ctrl+Tab уходит к следующему полю; Backspace в отступе откатывает на стоп; Enter копирует отступ, после `{ ( [` на уровень глубже, между `{}` ставит `}` на отдельную строку; Ctrl+A, C, X, V; Ctrl+Z — отмена, Ctrl+Y и Ctrl+Shift+Z — возврат (до 1000 шагов; печать и удаление по одному знаку — один шаг).
- **Мышь.** Клик — каретка, перетаскивание — выделение (за краем прокручивает), двойной клик — слово, тройной — строка, клик по номеру — строка; полосы прокрутки тянутся, клик по дорожке прыгает; колесо — 3 строки.
- **Тысячи строк.** Рисуются только видимые строки; текст хранится по строкам, правка трогает только их. Подсветка считается по требованию, построчно, с состоянием на конец строки (открытый комментарий, длинная строка, тег на несколько строк); после правки пересчитывается то, что смотрят. 20 000 строк: загрузка 3 мс, 200 нажатий в середине текста 0,1 мс, подсветка нижних строк после правки наверху 6–8 мс один раз (замер в `tools/ui_test`, не в игре).
- **Окончания строк.** Модель помнит окончание файла (`CRLF` или `LF`, по большинству) и пишет его обратно; смешанный текст выравнивается по большинству.
- **Из кода.** `Window.GetCodeEdit("code")` — модель `CodeEdit`: `Text`, `Caret`/`Anchor`, `GoTo`, `Select`, `Replace(от, до, текст)`, `Undo`/`Redo`, `LineCount`, `Line(i)`; её правки доходят до `value`, модели и `oninput` на следующем кадре. `Window.RevealCaret(id)` — показать каретку. `Core/CodeLexer.cs` — отдельно: `CodeLexer.Scan(язык, строка, состояние, список)`.
- Подсветка простая, построчная, не разбор: XML (теги, атрибуты, значения, сущности, комментарии, CDATA, `<?…?>`), Lua (слова, длинные `--[[ ]]` и `[==[ ]==]`, числа), C# (слова и встроенные типы, `@"…"`, `"""…"""`, `/* */`, `#region`; строка с `$` — одним куском, внутри неё скобки не разбираются).

### Картинки на холсте: `Window.Images`

```csharp
Window.SetCanvas("pic", (sb, r) => Window.Images.Draw(sb, path, r, ImageFit.Contain));
Window.Images.DrawRegion(sb, tex, ImageLayout.Cell … , r);   // ячейка листа спрайтов
```

- `Images.Get(path)` — `Texture2D` из файла PNG/JPG/BMP/GIF/TGA (загрузчик игры, без сжатия): один раз на файл, дальше тот же; пропавший или битый файл — `null` и одна строка в журнале. Файл смотрится раз в секунду: сохранён заново — читается заново. `Images.Add(ключ, байты)` — картинка не из файла (вставленная), `Peek`, `Release`, `Clear`.
- `Draw(sb, путь или текстура, прямоугольник, fit, tint, pixelPerfect)`: `ImageFit.Contain` (вся, по центру), `Cover` (заполнить, края срезать), `Stretch`, `Actual` (1:1 по центру), `ScaleDown` (то же, что `object-fit: scale-down`: меньше из `Actual` и `Contain`). `DrawRegion(sb, tex, источник, прямоугольник, …)` — часть картинки; `ImageLayout.Cell(w, h, столбцов, строк, номер)` — ячейка листа. `ImageLayout.Place` даёт те же числа без рисования, `PixelAt` — какой пиксель картинки под точкой (точки на холсте).
- `pixelPerfect`: целые масштабы и без сглаживания (пиксель-арт). Для этого пакет рисования переоткрывается на время вызова: давайте несколько больших картинок, а не сотни мелких.
- Память: все текстуры окна в одном бюджете: картинки холста и CSS (один файл — одна текстура), тени, градиенты, маски углов — до 256 МБ и 4096 записей. При переполнении уходят давно не рисованные, но не нарисованные в этом или прошлом кадре, за один проход до трёх четвертей бюджета. Освобождаются при закрытии окна и при уходе из бюджета, но с задержкой в долю секунды: пакет рисования мог ещё держать текстуру.

### Файлы: перетаскивание и Ctrl+V

В игре нет диалога выбора файла, поэтому два пути: **перетащить файл** из Проводника на окно игры и **вставить** из буфера.

```csharp
Window.SetFileInput("sprite", f => { Load(f.Path ?? SaveImage(f)); return true; }, accept: ".png,.jpg");
```

```html
<div id="sprite" tabindex="0">Перетащите файл сюда или нажмите здесь и Ctrl+V</div>
```

- Цель — блок по `id`. `accept`: расширения (`.png,.jpg`), `image/*` или пусто. Обработчик получает `UiFileInput`: `Source` (`Drop`, `PasteFile`, `PastePath`, `PasteImage`), `Path` (у вставленной картинки `null`), `ImageData` (байты PNG, а если в буфере был только битмап — BMP), `Extension`, `IsImage`, `Name`, `ReadBytes()`, `Target`, `Position`. Ответ `false` отдаёт файл следующей цели (предку).
- **Перетаскивание.** Игра получает от SDL событие `FileDropped` (путь файла); окно берёт файл, если под указателем в момент падения блок-цель этого окна (или потомок). Окно, у которого есть цели и которое накрыло точку, забирает файл у окон под ним, даже если цели в этой точке нет (окна без целей не в счёт). Верхнее окно — новейшее показанное.
- **Вставка.** Цель получает фокус по клику и по Tab (`tabindex="0"`), Ctrl+V тогда читает буфер по порядку: файлы, скопированные в Проводнике (`CF_HDROP`), картинка (формат `PNG` или битмап `CF_DIB`, например снимок экрана), текст с путём (в кавычках от «Копировать как путь», строка на файл, `file:///…`). Берётся то, что подходит под `accept`.
- Чего **нет**: подсветки цели во время перетаскивания (SDL в MonoGame не присылает события, пока файл в руке: только само падение) и точки падения от SDL (берётся место мыши в момент падения); перетаскивания из окна **в** Проводник; нескольких файлов за раз у цели (каждый приходит отдельным вызовом).
- Ограничение Windows: если игра запущена от администратора, а Проводник нет, система не отдаёт ей перетаскиваемые файлы. Буфер работает всегда.

Не проверено в игре (проверено сборкой, `tools/ui_test` и страницей `UI/inputs.html` в самотесте игры, который ещё не запускался): всё из этого раздела в игре — внешний вид, шрифт и ширина знака, захват мыши вне окна, события SDL, чтение буфера через user32/shell32.

## Видео

`<video>` играет WebM игровым декодером (`Barotrauma.Media.Video`, тем же, что заставки игры и видео меню BBE; файл форка не меняется). Не проверено в игре: декодер в ui_host работает, в игре пока нет.

```html
<video id="intro" src="media/clip.webm" autoplay loop muted poster="media/poster.png"></video>
<video id="once" src="media/clip.webm" volume="0.5"></video>
<button onclick="play('once')">Играть</button>
<button onclick="pause('once')">Пауза</button>
<button onclick="restart('once')">С начала</button>
```

- **Файл**: `src` — только `.webm`; путь как у `<img>` (от папки страницы, не выше пакета; адреса в сети, `data:` и абсолютные пути не принимаются). Нет файла или не WebM — блок-заглушка (тёмный прямоугольник) и одна строка в `baroui problems`.
- **Атрибуты**: `autoplay`, `loop`, `muted` (звук не выводится; декодер всё равно работает), `volume` (0..1, по умолчанию 1; вне диапазона обрезается, не число — 1, и строка в problems), `poster` (картинка файла: видна до первого кадра и когда видео не играет).
- **Размер**: натуральный размер — ширина и высота видеодорожки из заголовка WebM (декодер не нужен). CSS `width` без `height` даёт пропорции клипа; без файла заглушка 320 x 180 (16:9) до явного размера в CSS.
- **Вид**: `object-fit` как у `<img>` (по умолчанию `fill`); `object-position` нет (у картинок тоже нет). `opacity` и `border-radius` как у картинки: скругляется фон и рамка блока, а кадр и постер углы имеют прямые (то же ограничение, что у картинки в скруглённом блоке, см. REFERENCE).
- **Команды из разметки**: `play(id)`, `pause(id)`, `stop(id)` (то же, что пауза), `restart(id)`. Обработчики `onended` (клип дошёл до конца, без `loop`) и `onerror` (файл не играет или нет кадра за 5 с).
- **Из C#**: `Window.Video("intro")` — `Play()`, `Pause()`, `Stop()`, `Restart()`, `Volume` (чтение и запись, пишет атрибут `volume`), `IsPlaying`, `Duration` (из заголовка файла, до игры; `null`, если его нет). Для неизвестного id ничего не происходит (`Found` = false).
- **Жизнь и стоимость**: декодер работает только пока элемент нарисован на экране. Скрыт, прокручен за край, `visibility: hidden` — декодер выгружается; снова на экране — клип начинается сначала (в Video API нет перемотки и паузы с сохранением позиции). Пауза и стоп выгружают декодер. Выгрузка также при закрытии окна, `baroui reload`, удалении элемента и смене `src`.
- **Лимит**: не больше 2 декодеров на окно. Третий ждёт свободного слота и даёт одну строку в problems.
- **Память**: кадр — текстура элемента в бюджете текстур окна (как картинки), при вытеснении декодер выгружается и клип начнётся заново; текстура уходит через очередь (через 0,75 с, как картинки).
- **Звук**: `volume` и `muted` задают `AudioGain` игрового `Video` (громкость канала). Следует ли звук за настройкой громкости игры — по коду не подтверждено (категория звука видео не задана), не проверено в игре.
- **Потоки**: декодер копирует кадры в фоновом потоке, текстура обновляется на главном потоке в кадре окна.
- **Не сделано**: `controls`, перемотка, пауза с сохранением позиции, скругление кадра по `border-radius`, `object-position`, `<source>`.

## Графики: набор рисования, `<curve>`, `<chart>`, `<gauge>`

Полоса E (`docs/ui/DESIGN_CHARTS.md`). Геометрия и правила — `Core` (тесты в `tools/ui_test`, `DrawKitTests`, `ChartTests`); рисование — `Render/UiDraw.cs`, `Render/UiCharts.cs`. Страница-пример: `UI/charts.html` с данными `UI/charts.data.json`, снимок: `tools/ui_host --page own/BaroUI/UI/charts.html --data own/BaroUI/UI/charts.data.json --frames 90`.

### Набор рисования: `Window.Drawing` в `SetCanvas`

`Window.Drawing` (тип `UiDraw`) — то же, чем рисуют сами `<curve>`, `<chart>`, `<gauge>`. Текстуры (линии, круги, уголки) — в бюджете окна и освобождаются через кладбище, как и остальные текстуры окна.

- `Stroke(sb, path, width, color, corner, dashOn, dashOff, continuePhase)` — ломаная: стыки круглые (без выемок), прямые углы под прямым углом скругляются четвертью кольца радиусом `corner` px; `dashOn`/`dashOff` в px — пунктир с бегущей фазой (`continuePhase` продолжает фазу предыдущей линии).
- `Dots(sb, path, radius, color)`, `Disc(sb, center, r, color)`, `Ring(sb, center, outer, inner, color)`.
- `Arc(sb, path, cx, cy, r, a0, a1, width, color)`, `Sector(sb, cx, cy, r, a0, a1, color)` — углы в радианах, 0 — вверх, по часовой.
- `Area(sb, curve, baseY, color)` — сплошная область под кривой; `Fill(sb, outline, color)` — любой многоугольник. Градиента нет.
- `Text(sb, fonts, style, text, x, baseline, color, align)` — шрифт движка (`'l'`, `'c'`, `'r'`); `fonts` — `Window.Fonts` (тип `UiFonts`, публичное свойство окна), `style` — `ComputedStyle` элемента (`Window.Find("id").Style`).
- `UiPath` — путь: заполняйте `path.Raw` (список `DPt` в пикселях холста) и переиспользуйте список. Геометрия пересчитывается только при смене точек, ширины или радиуса; устоявшийся кадр без выделений.

```csharp
var line = new UiPath();
Window.SetCanvas("pad", (sb, r) =>
{
    line.Raw.Clear();
    line.Raw.Add(new DPt(0, r.Height)); line.Raw.Add(new DPt(r.Width / 2, 0)); line.Raw.Add(new DPt(r.Width, r.Height));
    Window.Drawing.Stroke(sb, line, 2, new Color(63, 182, 168), corner: 8);
});
```

### `<curve>`: редактируемая кривая

```html
<curve data-model="settings.damageByDepth" x-min="0" x-max="5000" y-min="0" y-max="3" snap="250 0.1" mode="smooth" monotone max-points="8"></curve>
```

- Значение — текст `x:y, x:y` (как `BBE.Curves.PointCurve`; игра читает его тем же разбором). Без `data-model` — атрибут `value`.
- Значение может быть списком точек: список или массив, элементы — `DPt`, пара `(x, y)`, массив или список из двух чисел, словарь с ключами `x`/`y` (или `X`/`Y`), объект с числовыми свойствами `X`/`Y`. Правка пишется обратно той же формы: список правится на месте (растёт и укорачивается), массив той же длины — на месте, другой длины — новый массив того же типа. Модель другой формы (не список точек) не читается: кривая пустая.
- `mode`: `linear` (по умолчанию), `smooth` (монотонная, без перелётов), `step` (значение держится до следующей точки). Режим в тексте не хранится.
- Мышь: тянуть точку; двойной щелчок на пустом месте — новая точка; правый щелчок по точке — убрать. Клавиатура (Tab встаёт на кривую): стрелки двигают выбранную точку на шаг сетки (`snap`, без сетки — сотая часть диапазона), Delete или Backspace убирает.
- Правила: первая и последняя точки сохраняют свой `x` (двигаются по `y`); точки не обгоняют соседей; `y` в `[y-min, y-max]`; `monotone` — `y` не убывает; `snap="sx sy"` — шаг сетки; `max-points` (по умолчанию 16), минимум две точки.
- События: `oninput` — на каждое движение, `onchange` — при отпускании и на добавление, удаление, шаг стрелкой.
- Вид (свойства CSS): `--series-1` цвет линии, `--stroke-width` толщина, `--point-size` диаметр точки, `--point-color` цвет точек, `--series-2` кольцо выбранной точки, `--grid-color` сетка, `background-color`, `border`, `height`.

### `<chart>`: график по данным модели

```html
<chart data-series="доход: stats.income; расход: stats.loss" type="area" format="0" y-min="0"></chart>
```

- `data-series` — ряды `имя: путь` через `;`; путь читается как в `data-model` (список чисел). Числа не из списка пропускаются.
- `type`: `line` (по умолчанию), `area`, `bar` (столбики с округлыми концами), `step`.
- Оси: деления «круглые» (1, 2, 5 × 10ⁿ), ось расширяется до целых делений; `y-min`/`y-max` задают границы явно; `format` — формат `.NET` подписей (`0`, `0.0`, `0 %`).
- Ось X (внизу, под графиком, только если задана): `x-labels="model.path"` — подписи категорий, список строк (при тесноте показывается каждая n-я); либо `x-min`/`x-max` — числовые деления (круглые) от `x-min` до `x-max`, категории размещаются равномерно между ними (по умолчанию `x-min` = 0, `x-max` = число точек − 1).
- Наведение: вертикальная линия и подсказка со значениями всех рядов. Щелчок по точке (столбику) — `onpick`. Индекс точки передаётся обработчику как `$arg` (`onpick="pick($arg)"`) и пишется в атрибут `data-picked` до вызова.
- Смена данных плавная: ряды догоняют новые значения за долю секунды.
- Вид: `--series-1`…`--series-6` цвета рядов, `--stroke-width`, `--grid-color`; подписи — `color` и шрифт элемента.

### `<gauge>`: прибор

```html
<gauge data-model="sub.depth" min="0" max="700" zones="500" ticks="8" format="0"></gauge>
<gauge data-model="reactor.load" min="0" max="100" zones="60, 85" fill="sector"></gauge>
```

- Значение — число по `data-model` (без модели — атрибут `value`), зажатое в `[min, max]`. Стрелка плавно догоняет значение.
- `zones` — пороги по возрастанию через запятую: ниже первого порога — зона 0, от порога — следующая. Цвет стрелки и дуга зон — по зоне значения.
- `fill="sector"` — заполненный сектор до значения вместо только стрелки. `ticks` — число делений (по умолчанию 5), `format` — подписи делений и значения.

### Графики: данные и жизнь элементов

- Кадр без изменений данных не выделяет память: значения читаются в буферы, подписи и подсказка пересобираются только при смене шкалы, индекса наведения или данных. Проверка — `tools/ui_test/ChartLaneTests.cs` (байты на горячем пути).
- Что ещё выделяет память (`Render/UiCharts.cs`, вне горячего пути кадра): массивы точек и `PointCurve` у `<curve>` в режиме `smooth` при каждом изменении точек (то есть на каждом шаге перетаскивания); массив значений ряда при смене числа точек; строки подписей и подсказки при смене шкалы или индекса наведения; новый `CurveEditor` при смене модели кривой; строка `data-picked` при щелчке; пути `UiPath` создаются один раз на ряд и при смене `data-series`.
- Элементы графиков без `id` получают ключ, привязанный к объекту элемента; когда `data-for`/`data-if` убирают элемент из окна, его обработчик мыши отбрасывается при появлении следующего графика (`Core/CanvasRegistry.cs`).
- Дуга от −135° до +135° (от вершины по часовой); высота элемента делится под дугу и подпись значения.
- Вид: `--zone-0`…`--zone-3` цвета зон, `--needle` стрелка, `--track-color` и `--track-width` дуга, `--tick-color` деления.

Проверено: сборка (`cscheck`), `tools/ui_test` (правила, геометрия, подбор делений), `tools/ui_host` (страница рисуется; перетаскивание точки и фокус щелчком — да). Не проверено: клавиши кривой (`ui_host` не доставляет клавиши фокусу, это проверяет самотест игры), сама игра. Нет: градиентной заливки, логарифмических осей, масштабирования колесом, фокуса на `<chart>` и `<gauge>` с клавиатуры. Фокус `<curve>` с клавиатуры есть (Tab, стрелки, Delete).

## Значки

Значки пяти видов; первый — самый удобный:

0. **Значок по имени (шрифт Lucide).** `<i data-icon="trash-2"></i>` — движок ставит в элемент символ значка с этим именем, стандартное правило даёт ему `font-family: lucide` (2379 значков; имена как на lucide.dev: `check`, `x`, `plus`, `trash-2`, `settings`, `search`, `star`, `alert-triangle`, `chevron-down`…; список — `Fonts/lucide-codepoints.json`). Значок — это текст: размер — `font-size`, цвет — `color`, работают `text-shadow` и `scale`; стоит на базовой линии и высотой 1em. Имя можно привязать: `data-icon="{{n.icon}}"`. Незнакомое имя — значка нет и одна строка в журнале. Можно и руками: `font-family: lucide` и символ кода из таблицы. Шрифт `Fonts/Lucide.ttf`, лицензия ISC (`Fonts/LICENSE-Lucide.txt`); в игре не проверен.

1. **Символы Юникода шрифтом.** Моно-шрифт окна (`JetBrains Mono`, по умолчанию) знает стрелки и фигуры: `▲ ▼ ► ◄ ▶ ◀ ✓ ✗ ✕ × ⚠ ● ○ ■ □ ◆ ◇ ← → ↑ ↓ ≡ … • –`. Нет в нём (рисуется пустой квадрат или пропуск): `★ ☆ ♥ ✔ ✘ ⚙ ☰ ⌕ ✖`. Размер, цвет, `text-shadow` и масштаб работают как у текста, поэтому `<span class="ico">⚠</span>` с `color` и `font-size` — самый дешёвый значок. Проверено по таблице символов (cmap) файлов шрифтов; с другими семействами (`font-family: serif` и т. п.) набор меньше, запасной шрифт для пропущенных символов не проверялся (что рисуется вместо них, неизвестно).
2. **Спрайты игры** — `<item sprite="вид:id">` и `background-image: sprite(вид:id)` / `<img src="sprite(вид:id)">`: `talent:` `faction:` `mission:` `job:` `item:` `affliction:` (значок недуга) и `ui:` (значок интерфейса игры: именованный спрайт стилей, например `ui:speechbubbleicon`, `ui:outposticon`, `ui:wreckicon`, `ui:enemyicon`, иначе первая картинка стиля компонента, `ui:guibuttonsettings`). Нет такого — одна строка в журнале, значка нет.
3. **Файл-картинка** (PNG с прозрачностью): `background-image: url("icons.png")` с `background-position` и `background-size`, как лист спрайтов: блок размером с значок, `background-position: -32px -64px`, `background-repeat: no-repeat`. Растровый, поэтому при масштабе мягчеет.
4. Другие иконочные шрифты (Material Symbols, Phosphor) не подключены; Lucide выше закрывает то же.

## Свои шрифты: `@font-face`, `BaroUi.RegisterFont`

Шрифт мода — файл `.ttf` или `.otf` в пакете мода (папка `Fonts/`; лицензию OFL или свою положите рядом). Пример: `own/BaroUI_Example` (`Fonts/Caveat-Bold.ttf`, заголовок в `UI/example.css`).

```css
@font-face {
  font-family: "Мой шрифт";
  src: url("../Fonts/MyFont-Regular.ttf") format("truetype"), url("../Fonts/MyFont.otf");
  font-weight: 400;      /* normal, bold, 1..1000 */
  font-style: normal;    /* normal, italic, oblique */
}
@font-face { font-family: "Мой шрифт"; src: url("../Fonts/MyFont-Bold.ttf"); font-weight: bold; }
h1 { font-family: "Мой шрифт", sans-serif; }
```

- Путь к файлу — от папки страницы (`UI/`), как у картинок (`ImageCss.ResolvePath`): внутри пакета (рядом с `filelist.xml`), не выше него. Адреса в сети, `data:`, `file:` и абсолютные пути не принимаются; ничего не скачивается.
- `src` — список `url(...)` через запятую: берётся первый читаемый. `format(...)` игнорируется; `local()` не поддерживается (пропускается с замечанием).
- Блоки с одним семейством — разные начертания: `font-weight` (число 1..1000, `normal` 400, `bold` 700; диапазон `100 900` даёт первое число с замечанием) и `font-style` (`italic`, `oblique`). Выбор начертания тот же, что у встроенных семейств: ближайший вес; курсива нет в файле — наклон. Дескрипторы `font-display`, `unicode-range` и прочие не поддерживаются (замечание, блок остаётся).
- Метрики (высота строки) берутся из таблиц файла (`hhea`, иначе `OS/2`), без внешней библиотеки. Файл — TrueType или OpenType с CFF; коллекции `.ttc`, WOFF и WOFF2 не принимаются.
- Область видимости: семейство видно окнам, чьи таблицы стилей его объявляют. В окне оно перекрывает встроенное семейство с тем же именем только в этом окне; глобальная таблица (`Core/FontFamilies.cs`) не меняется.
- Нет файла или он не читается: семейство не появляется; список `font-family` идёт к следующему имени, потом к шрифту по умолчанию. Одна строка в `baroui problems` (`bbe_ui problems`) на правило.
- Память: шрифты мода идут через тот же кэш, что встроенные (`Core/FontCache.cs`); закрытое окно отдаёт свои грани (`UiFonts.Release`), и они уходят по обычным правилам (простой, предел). Последний шрифт файла остаётся якорем, как у встроенных.

Из C#, для кода мода: `BaroUi.RegisterFont(string family, string file, int weight = 400, bool italic = false)` — путь абсолютный (файл вашего пакета), действует на окна, открытые после вызова. Имя семейства — одно (без запятых). Неверные аргументы бросают `ArgumentException`; отсутствующий файл — строка в `problems` окна, как у CSS. Список: `docs/ui/API.md`.

## Шаблоны и события

| Разметка | Что делает |
|---|---|
| `{{ship.depth}}`, `{{x \| 000}}`, `{{v \| 0.0}}` | значение из `Data`; формат — как в .NET (`0`, `#`, `.`, `,`, `F1`) |
| `data-for="r in rows"` + `data-key="r.id"` | повтор; строки с тем же ключом переиспользуются. От 100 строк внутри `overflow: auto` список виртуальный (или `data-virtual`), высота строк одинаковая |
| `data-if="fuel > 0"` | элемент есть, только если условие истинно |
| `data-class="low: fuel < 20; warn: alarm"` | классы по условиям |
| `data-disabled="busy"` | `disabled` по условию |
| `data-model="name"` | поле ↔ данные в обе стороны |
| `data-t="id"`, `data-t-title="id"`, `data-t-placeholder="id"` | перевод: текст по id берётся из `TextManager` игры (`Api/BaroUi.cs`). Пакет добавляет свои тексты так же, как `own/BBE_Mods`: в `filelist.xml` строкой `<Text file="%ModDir%/Localization/English.xml" />` (и `Russian.xml`); сам `own/BaroUI` текстов не несёт, папки `Localization` у него нет. Так подключены соседние пакеты; в игре с этой страницей не проверено. Подставляется в элемент вместо его содержимого, в атрибут `title`/`placeholder` (любой `data-t-<атрибут>`). В тексте можно `{{…}}`: он связывается после подстановки. Нет текста с таким id: замечание страницы (`baroui problems`), элемент остаётся как в разметке. Подставляется при чтении страницы, поэтому страница, открытая после смены языка, уже на новом |
| `onclick="craft(r.id)"`, `oninput`, `onchange`, `onenter`, `onfocus`, `onblur`, `onclose`, `onsave` (Ctrl+S в `<textarea>`) | методы `[UiHandler]` класса окна; аргументы — выражения, `this` — сам элемент |
| `onpick="pick($arg)"` | `<chart>`: щелчок по точке или столбику; индекс передаётся обработчику как `$arg` и пишется в `data-picked` до вызова |
| `close()`, `showModal(id)`, `closeDialog(id?)`, `focus(id)` | встроенные обработчики |

Выражения: пути `a.b[0].c` (регистр имён не важен), числа, `'строки'`, `true/false/null`, `$index`, `+ - * / %`, сравнения, `&& || !`, скобки. Вызовов функций и присваиваний нет: шаблон только читает данные, меняет их C#.

## Инструменты

| Команда в консоли игры | Что делает |
|---|---|
| `baroui open <page>` / `close [page]` / `list` | открыть страницу `UI/<page>.html` (модель без вида: `UI/<page>.data.json`), закрыть, список окон |
| `baroui reload [page]` | перечитать HTML и CSS на месте: данные, класс C#, подписчики и прокрутка сохраняются. C# не перезагружается |
| `baroui watch [on\|off]` | перезагружать окно при каждом сохранении файла и показывать плашку ошибок |
| `baroui anim [on\|off]` | выключить или включить все анимации окон (переходы, ключевые кадры, печатная машинка): изменения происходят сразу, текст виден целиком |
| `baroui anim fps N\|max` | частота выборки анимируемых длин по умолчанию (30); `max` — каждый кадр. Своё значение блока `layout-fps` главнее |
| `baroui debug [on\|off]` | контуры всех блоков; под мышью — поля (оранжевые), отступы (зелёные), содержимое (синее), селектор, размеры в u и px, строка в HTML; плашка ошибок |
| `baroui problems [page]` | все замечания окна в консоль: `файл:строка: текст` |
| `baroui src <папка>\|off` | брать страницы из рабочей копии (например `own/BaroUI/UI` репозитория), а не из установленного пакета |

**Эталонные снимки страниц** — без игры, на `ui_host` (нужна сборка `tools/ui_host`, игра не запускается; шрифт Noto Sans берётся из папки игры, только чтением). **Эталонов пока нет**: `tools/ui_host/refs` не создана, поэтому каждая страница сейчас даёт `FAIL ... no reference`. Создать: собрать `ui_host`, посмотреть `tools/ui_host/out/*.png`, затем `snap.py --update` (запишет `refs/` и `manifest.json`; `manifest.json` помнит, был ли при записи Noto Sans):

```bash
cd tools/ui_host && dotnet build -c Release && cd ../..
py -X utf8 tools/ui_host/snap.py            # рисует страницы из PAGES в tools/ui_host/out, сравнивает с tools/ui_host/refs (пока без эталонов: FAIL)
py -X utf8 tools/ui_host/snap.py --only controls
py -X utf8 tools/ui_host/snap.py --update   # записать эталоны (сначала посмотреть out/diff и out/*.png глазами)
py -X utf8 tools/ui_host/snap.py --selftest # проверка самого сравнения на синтетических картинках
```

Пиксель считается отличающимся, если какой-то канал отличается больше чем на `--tol` (8 из 255); страница не совпала, если доля отличных пикселей больше `--share` (0,001). Несовпадение: код 1, `out/diff/<страница>.png` (красным отличные пиксели, эталон приглушён). Нет эталона или размер другой — тоже несовпадение. Список страниц в начале `snap.py`; `manifest.json` в `refs/` записывает, был ли Noto Sans при записи эталонов. Нужны `numpy` и `PIL` (ничего не скачивается).

**Предпросмотр в браузере** — без игры:

```bash
py -X utf8 tools/ui_preview.py
```

Откройте `http://127.0.0.1:8766/?page=controls`. Тестовые данные лежат в `tools/ui_preview/data/<page>.json`, их можно править прямо на странице. Игровые теги показываются заглушками. Сохранили файл — страница перерисовалась. Другая папка страниц: `--ui own/BBE_Terminal/UI`. Страница в другом состоянии: `&data=<имя>` берёт `data/<имя>.json` вместо `data/<page>.json` (лобби: `lobby_subs`, `lobby_load`), `&set=путь:значение` меняет одно поле после загрузки, `&dialog=<id>` открывает окно.

Браузер и игра расходятся в мелочах: FreeType округляет ширину символа, поэтому в игре строки чуть шире. Окончательная проверка — в игре, с `baroui watch`.
