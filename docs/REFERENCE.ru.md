## 1. Что это и как работает

### 1.1. Суть

BBE UI — собственный движок HTML/CSS для игры Barotrauma. Браузера в игре нет: разбор HTML, каскад CSS, раскладка и рисование сделаны в C#. Поддерживается только то, что перечислено в этой справке. Всё неизвестное пропускается с замечанием в журнале и на плашке ошибок (`baroui watch`, `baroui debug`, `baroui problems`).

Конвейер (проверено по коду, порядок вызовов в `Render/UiWindow.cs`):

| Этап | Файлы | Что делает |
|---|---|---|
| разбор HTML | `Core/HtmlParser.cs`, `Core/Dom.cs` | дерево `Element`/`TextNode`, void-теги, сырой текст у `style`, `script`, `textarea`, таблица сущностей |
| разбор CSS | `Core/CssParser.cs`, `Core/CssValues.cs` | правила, селекторы, объявления, `@keyframes`; `@media`, `@import`, `@font-face` пропускаются с замечанием |
| данные | `Core/Template.cs`, `Core/Expr.cs` | `{{…}}`, `data-for`, `data-if`, `data-class`, `data-model`, `data-t`, обработчики |
| каскад | `Core/StyleEngine.cs` | значения, наследование, `var()`, `!important`, состояния (`:hover` и др.), кэш стилей |
| раскладка | `Core/LayoutEngine.cs`, `Core/LayoutBox.cs` | блочная, строчная, flex, grid, позиционирование, инкрементальная раскладка |
| анимации | `Core/Animation.cs`, `Core/Easing.cs` | переходы, `@keyframes`, `layout`-переход, печатная машинка |
| рисование | `Render/Painter.cs`, `Render/UiDraw.cs`, `Render/UiCharts.cs`, `Render/UiControls.cs`, `Render/UiImages.cs`, `Render/UiFonts.cs` | `SpriteBatch` игры, фон, рамки, тени, градиенты, текст, поля, графики |
| ввод | `Core/PointerRouter.cs`, `Core/KeyRouter.cs`, `Core/DragDrop.cs`, `Core/Popup.cs`, `Core/FocusOrder.cs`, `Render/UiCanvasInput.cs`, `Render/UiFileInput.cs` | мышь, клавиши, фокус, перетаскивание, всплывающие окна, файлы |
| координаты | `Core/ScreenMap.cs`, `Core/UiTransform.cs` | одно место, где считается «где элемент на экране» (рисование, мышь, IME, подсказки) |

Ядро (`Core/`) не зависит от игры: его тесты запускаются без игры (`tools/ui_test`). `Render/` и `Api/` работают только внутри игры.

### 1.2. Единицы и холст

- `1u = min(ширина экрана / 1600, высота экрана / 900) × HUD-масштаб игры` (проверено по коду: `Render/UiWindow.cs`, строка 630, `UnitPx`).
- `px` — значение берётся как написано, без умножения на `UnitPx` (проверено по коду: `Core/StyleEngine.cs`, расчёт `FontSizePx`, ветка `Unit.Px`). (не проверено по коду: совпадает ли 1 px с пикселем экрана при нецелом HUD-масштабе.)
- `em` — размер шрифта элемента; для `font-size` — размер шрифта родителя.
- `%` — от той стороны или величины, которую задаёт свойство (см. таблицу свойств).
- Холст страницы — **1600u × 900u**, по центру экрана. Если экран другой пропорции, остаток остаётся пустым (проверено по коду: `UiWindow.cs`, строки 646–648).
- `<html data-viewport="screen">` (или `<body>`): вьюпорт раскладки — весь экран, `position: fixed` и проценты считаются от краёв экрана. Единица `u` при этом та же. Предпросмотр в браузере этот режим не показывает (по AUTHORING; проверено по коду: `Core/Dom.cs`, `Document.ScreenViewport`).
- Комментарий в `Core/CssValues.cs` (строка 7) говорил, что `u` — это 1/1600 ширины окна. Исправлен 2026-11-16: теперь он даёт формулу выше; поведение кода не менялось.

### 1.3. Где работает

- Это **LuaCs C#-мод**: `own/BBE_UI/ModConfig.xml` подключает сборки `CSharp/Shared` (`IsScript="true"`, `FriendlyName="BaroUI"`) и `CSharp/Client` (`Target="Client"`, то же имя) (проверено по коду: `ModConfig.xml`).
- Игра и LuaCs перехватываются через Harmony (проверено по коду: `Api/BaroUi.cs`, `Init`):
  - префикс `DebugConsole.AddToGUIUpdateList` — здесь окна получают кадр и ввод;
  - префикс меню паузы — Esc (`PauseMenuPrefix`).
- **Где видны окна**: в главном меню — только если LuaCs держит моды запущенными в меню. Это форк BBE (`forks/LuaCs`, ветки `luacs/bbe` и `moonsharp/bbe`; по HANDOFF). Обычный (stock) LuaCs в меню выгружает моды, поэтому окна там не работают; в лобби, раунде и редакторах stock LuaCs работает (по `docs/HANDOFF.md` и `docs/luacs/COMPARE_PLUGIN.md`; (не проверено в игре) для каждого сценария по отдельности).
- JavaScript нет. Сети нет: адреса `http(s)://`, `data:` и `file:` не загружаются (проверено по коду: `Core/ImageLayout.cs`, `ResolvePath`).

### 2.2. Минимальная страница

`own/BBE_UI/UI/fuel.html`:

```html
<!doctype html>
<html>
<head>
  <link rel="stylesheet" href="fuel.css">
</head>
<body>
  <div id="root" class="panel">
    <p class="title">Топливо</p>
    <div class="gauge"><div class="fill" style="width: {{level}}%"></div></div>
    <p>Уровень: {{level}}</p>
    <button onclick="refill(1)">Заправить</button>
  </div>
</body>
</html>
```

`own/BBE_UI/UI/fuel.css`:

```css
.panel { width: 400u; padding: 16u; background-color: #0b1418; border: 1u solid #4a6a6c; border-radius: 6u; }
.gauge { height: 14u; background-color: #1d3a3f; }
.fill { height: 100%; background-color: #40c8be; }
```

Класс C#:

```csharp
using BaroUI.Api;
using BaroUI.Core;

public sealed class FuelView : BaroUiView
{
    protected override void OnOpen() => Data = new { level = 40 };

    [UiHandler]
    private void refill(int id)
    {
        // сообщение серверу; ответ сервера обновит Data через Refresh()
        Send(Find("#root"), () => { /* отправка */ });
    }
}

// открыть:
BaroUi.Open<FuelView>(Path.Combine(pkgDir, "UI", "fuel.html"));
```

Замечания по примеру (проверено по коду):

- Обработчики `[UiHandler]` — методы класса окна; имя метода — имя в атрибуте `onclick`; приватные тоже подходят (`Core/Template.cs`, `Handlers`, метод регистрации: «public or not»).
- `Data` — объект C# или словарь; после изменения вызывается `Refresh()`; точечно — `Set("level", 42)` (`BaroUiView.Set`, `UiWindow.Set`).
- Вызов `Send(...)` блокирует элемент до ответа (по умолчанию 5 с) и добавляет класс `pending` (проверено по коду: `Api/BaroUiView.cs`, `Send`/`Done`). Элемент должен вызвать `Done(source)`.
- (по AUTHORING) Окно не меняет данные игры само: изменения идут через сервер, окно ждёт ответа.

Важно: в примере `Find("#root")` — это `BaroUiView.Find(selector)` по CSS-селектору; `UiWindow.Find(id)` принимает только `id`.

### 2.3. Жизненный цикл класса окна

Методы `BaroUiView` (проверено по коду: `Api/BaroUiView.cs`):

| Метод | Когда вызывается |
|---|---|
| `protected virtual void OnOpen()` | после создания окна и первой раскладки |
| `protected virtual void OnUpdate(float deltaTime)` | каждый кадр |
| `protected virtual void OnAfterInput()` | после обработки ввода кадра |
| `protected virtual void OnClose()` | при закрытии |

(OnUpdate и OnAfterInput вызываются из `UiWindow`; точный порядок относительно раскладки в этой сверке не перечитан — (не проверено по коду).)

### 2.4. Открыть страницу

```csharp
// свободное окно: Esc и клик мимо окна обрабатывает движок (Esc уходит ему, если окно верхнее)
UiWindow w = BaroUi.Open(path, view, "fuel");
var w2 = BaroUi.Open<FuelView>(path);              // с новым экземпляром класса T
UiWindow w3 = BaroUi.OpenPage("controls");         // UI/controls.html текущего пакета (или из baroui src)
```

Функции `Open` добавляют окно в список свободных (`windows`), которые получают кадр и ввод (`Api/BaroUi.cs`, `Open`).

### 2.5. Окно предмета (hosted window)

Компонент предмета (как терминал, `own/BBE_Terminal/CSharp/Client/TerminalUi.cs`) создаёт окно так:

```csharp
// окно не свободное: компонент сам добавляет его в список обновления и закрывает его
window = BaroUi.Create(path, view, "term");
// в AddToGUIUpdateList компонента:
window.AddToGUIUpdateList(order);
// закрыть при снятии выбора:
window.Close();
```

Esc и клик мимо окна обрабатывает игра: `GuiFrame` компонента — невидимый `GUIFrame`, который каждый кадр ставится на прямоугольник корневого блока (по AUTHORING: `window.BoxOf(window.Find("term"))`; для поля и подсказок точное место на экране даёт `ScreenRect`, см. раздел 4.9).

(по AUTHORING; проверено по коду: `Api/BaroUi.cs`, `Create` кладёт окно в список `hosted`, которое обслуживает `AddWindowsPrefix`.)

Для таких окон работают `baroui reload` и `watch`. Владелец, который хранит ссылку на окно, подписывается на `BaroUi.Reloaded` и подменяет ссылку (`Api/BaroUi.cs`, `public static event Action<UiWindow, UiWindow> Reloaded`; (порядок аргументов — старое/новое — не проверено по коду)).

`window.CaptureNextDraw("файл.png", "id")` — снимок блока после следующей отрисовки (проверено по коду: `UiWindow.cs`, `CaptureNextDraw`).

## 3. HTML: теги, атрибуты, контролы, шаблоны, события

### 3.1. Разбор разметки

- Разбор терпимый: лишний закрывающий тег закрывает ближайшего подходящего предка или игнорируется (`Core/HtmlParser.cs`, комментарий к классу; проверено по коду).
- Комментарии `<!-- … -->` пропускаются (по AUTHORING; (не проверено по коду: отдельная ветка для комментария)). `<!doctype html>` в примерах пишется; его обработка не проверена (не проверено по коду).
- Сырой текст (не разметка): `style`, `script`, `textarea` (проверено по коду: `RawText`, `HtmlParser.cs`). У `textarea` содержимое — это значение поля.
- Void-теги (без закрывающего, проверено по коду: `Void`, `Core/HtmlParser.cs`): `br`, `hr`, `img`, `input`, `meta`, `link`, `item`, `slot`.
- Именованные сущности (проверено по коду: таблица `Entities`): `&amp; &lt; &gt; &quot; &apos; &nbsp; &times; &mdash; &ndash; &hellip; &rarr; &larr; &uarr; &darr; &middot; &deg; &laquo; &raquo; &numero; &minus; &plusmn;`. Числовые ссылки `&#NNN;` (не проверено по коду). Для символов вне списка используйте сам символ в UTF-8.
- `<bar>` удалён из движка (2026-11-16, решение по пункту 15 сверки): ни одна страница, ни пакет и ни код его не использовали, отрисовки не было, он был только в списке void-тегов и в UA. Теперь это неизвестный тег; в страницах его нет, поведение неизвестного тега в раскладке не проверено по коду.
- Кодировка: файлы страниц — UTF-8 (по AUTHORING; (не проверено по коду: явная проверка кодировки)).

Отдельные замечания (проверено по коду):

- **Размер `<img>`.** Если CSS оставил сторону `auto`, берётся размер файла в пикселях (`Core/LayoutEngine.cs`, `IImageSizes`). Одна сторона в `px`/`u`/`em` — вторая по пропорциям картинки. Файла нет — блок 0 × 0. Вместо ненайденной картинки рисуется `alt` одной строкой (по AUTHORING).
- **`<option>`** не рисуется; строки списка берутся из дочерних `option` (`UiControls.OptionsOf`).
- **`<label>`** — при клике вызывается `ClickLabel` (`Render/UiControls.cs`, строки 413 и 425). Что именно передаётся связанному полю — (не проверено по коду).
- **`<a>`** становится фокусируемым и кликабельным только с `onclick` (`UiControls.cs`, строка 255); без `onclick` `a` — это текст.

### 3.3. Атрибуты

Общие (проверено по коду, если не указано иное):

| Атрибут | Действие |
|---|---|
| `id` | имя для `Find(id)`, `focus('id')`, `showModal('id')`, `SetCanvas(id, …)`, `SetFileInput(id, …)` |
| `class` | классы для селекторов; `data-class` меняет их по условиям |
| `style` | встроенное объявление: сильнее любого селектора (по AUTHORING) |
| `tabindex` | `-1`, `0` или положительное число: фокус и порядок Tab (раздел 5.3) |
| `title` | подсказка; появляется через 0,4 с наведения (`UiControls.cs`, `TooltipDelay = 0.4f`); в игре, не в предпросмотре |
| `accesskey` | одна буква: Alt+буква нажимает элемент или фокусирует поле (`UiControls.cs`) |
| `lang` | язык; `ru` (или отсутствие `lang`) включает склейку русских слов при `-bbe-ru-glue: auto` (раздел 4.6) |
| `data-*` | см. разделы ниже; неизвестные `data-*` игнорируются (по AUTHORING) |

Атрибуты контролов:

| Атрибут | Где | Действие |
|---|---|---|
| `type` | `input` | `text` (по умолчанию), `number`, `password`, `search`, `checkbox`, `radio`, `range`. Другие значения (`email`, `date`, `color` и т.п.) не распознаются как поля: `IsText`, `IsCheckbox`, `IsRadio`, `IsRange` их не узнают (`UiControls.cs`, строки 128–135); как рисуются — (не проверено по коду) |
| `name` | `input type=radio` | группа радио в окне |
| `value` | `input`, `option`, `progress`, `textarea`, `curve`, `chart`, `gauge` | значение; у `textarea` — содержимое тега |
| `checked` | `input` | отмечен (`:checked`) |
| `placeholder` | `input`, `textarea` | подсказка пустого поля (`UiControls.cs`, `UiCodeEdit.cs`) |
| `maxlength` | `input` текстовый | ограничение длины (`UiControls.cs`, строка 161, `MaxLength`) |
| `disabled` | элемент с контролом | не реагирует, `:disabled` (`UiWindow.IsDisabled`) |
| `readonly` | `textarea` | только чтение (`UiCodeEdit.cs`) |
| `autofocus` | поле внутри `dialog` | фокус при открытии модального окна (`UiControls.cs`, строки 573–585) |
| `min`, `max`, `step` | `input type=number`, `range` | границы и шаг; `step="any"` — без сетки у ползунка (по AUTHORING) |

| `src`, `alt` | `img` | файл и текст вместо картинки |
| `href`, `rel` | `link` | `rel="stylesheet"`, путь от папки страницы |

| `inventory`, `index` | `slot` | ячейка инвентаря; имя из `Window.SetInventory` (раздел 8) |
| `data-lang`, `tabsize`, `data-tabs`, `data-autoindent`, `data-gutter` | `textarea` | редактор кода (раздел 5.6) |
| `data-viewport` | `html`, `body` | экран вместо холста (раздел 1.2) |
| `data-picked` | `chart` | индекс точки, выбранной щелчком (ставит движок до `onpick`) |

### 3.4. Игровые теги и значения

- `<item prefab="oxygentank" count="3">` — иконка предмета игры; `prefab` ищется по имени, неизвестное имя — строка в журнале «no such item» (`UiControls.cs`, строка 1270 и далее).
- `<item sprite="item:oxygentank">`, `sprite="talent:…"` и т.п. — спрайт игры (раздел 7.3).
- `<canvas id="scope">` — рисует C#: `Window.SetCanvas("scope", (sb, rect) => …)` (раздел 8). Мышь — `SetCanvasMouse`, картинки из файлов — `Window.Images` (раздел 6).
- `<textarea id="code" data-lang="xml">` — редактор кода (раздел 5.6).
- `<slot inventory="in" index="0">` — ячейка инвентаря игры (`Window.SetInventory("in", inventory)`). Перетаскивание, подсказки и стопки работают, пока игра сама обновляет инвентарь. Размер задаёт CSS; полоску состояния игра рисует над ячейкой — оставьте место сверху. Ячейка, прокрученная за край или накрытая `dialog`, мышь не берёт. После `SetInventory(name, null)` или закрытия окна ячейки возвращаются игре (по AUTHORING).
  - Рамка ячейки — `-bbe-slot-frame` (не наследуется): `game` (по умолчанию, спрайт игры), `none` (рамки нет: видно оформление самого `<slot>`; игра рисует предмет, полоску состояния и стопку), `url("рамка.png")` (своя картинка, растягивается на ячейку). Не найдена картинка — рамка игры и строка в журнале (проверено по коду: `Render/UiControls.cs`, `SlotFrame`; не проверено в игре).
- `<dialog id="…">` — модальное окно (раздел 5.5).
- `<progress value max>` — без `value` — бегущая полоса (по AUTHORING; (не проверено по коду: анимация бегущей полосы)).
- `<curve>`, `<chart>`, `<gauge>` — раздел 6.

### 3.5. Поля, флажки, радио, ползунок, список, кнопка

Общее (проверено по коду `Render/UiControls.cs` и `Core/TextEdit.cs`, если не указано иное):

- Текстовое поле (`text`, `number`, `password`, `search`) получает клавиатуру и IME; персонаж в игре при этом не управляется.
- Фокус по щелчку: поля ввода и редактор кода берут фокус сами; любой элемент с явным `tabindex` (включая `-1`) тоже. Кнопки, флажки, радио, ползунки и списки **без** `tabindex` по щелчку фокус не берут — они берут клавиатуру только по Tab (по AUTHORING, раздел 5.3). Набор элементов, которые Tab вообще может остановить, — `UiControls.cs`, строка 255 (проверено по коду).

#### 3.5.1. Текстовое поле

Клавиши (проверено по коду `TextEdit.cs` и `UiControls.cs`, если не указано иное):

- Стрелки влево и вправо; Ctrl+стрелки — по слову (`TextEdit.WordLeft`, `WordRight`); Shift — выделение.
- Home, End; Ctrl+A — выделить всё (`SelectAll`).
- Backspace, Delete; Ctrl+Backspace и Ctrl+Delete — по слову (`TextEdit.Backspace(word)`, `Delete(word)`).
- Enter: если у поля есть `onenter`, вызывается он; иначе нажимается кнопка с `data-default` в ближайшем `dialog` или окне (`UiControls.cs`, строки 937 и 989–993).
- Ctrl+C, Ctrl+X, Ctrl+V — буфер обмена (по AUTHORING). Для `password` копирование и вырезание запрещены (`UiControls.cs`, строки 870 и 873).
- Esc: закрывает открытый список, затем диалог, затем окно (раздел 5.8).
- Tab и Shift+Tab — переход по порядку фокуса (раздел 5.3).
- Лимит длины — `maxlength` (`MaxLength`). Фильтр символов: `number` принимает цифры, `-`, `+`, `.`, `,`, `e`, `E` (`NumberField.Accept`, `Core/TextEdit.cs`).

Мышь:

- Щелчок ставит каретку (`TextEdit.IndexAt`); протягивание выделяет.
- Двойной и тройной щелчок — (не проверено по коду для полей; для редактора кода — см. раздел 5.6).

IME: движок отдаёт игре прямоугольник поля на экране (`UiControls.cs`, строки 59 и 1120), поэтому окно ввода IME стоит у каретки. Сама композиция (предварительный ввод) идёт в игре; (не проверено по коду и в игре).

`number`:

- Вверх и вниз — шаг `step` (по умолчанию 1), значение округляется по сетке и ограничивается `min` и `max` (`UiControls.cs`, строки 693–714 и 932–933; `NumberField.Clamp`).
- Колесо мыши над полем числа (проверено по коду, с 2026-11-16: `UiControls.Wheel` → `WheelNumber`, `Render/UiControls.cs`; шаг и пределы — `NumberField.Stepped`, `Core/TextEdit.cs`, тест `ControlsTests.cs`, группа «controls»): меняет поле под указателем на один шаг за щелчок, вверх — больше. С фокусом — как стрелка: `oninput` сразу, `onchange` при уходе из поля. Без фокуса — значение меняется сразу, `oninput` и `onchange` приходят сразу, модель пишется. На пределе колесо не используется, и страница под ним листает. Колесо внутри открытого списка и редактора кода — прежнее. (не проверено в игре: сама механика колеса в игре.)
- Значение записывается в модель при уходе из поля (`UiControls.cs`, функция `Commit`; по AUTHORING).

`password`: на экране `*` на каждый символ (`UiControls.cs`, строки 1044–1045).

`search`: поведение как у текстового поля; отдельного поведения (очистка по Esc и т.п.) не найдено (не проверено по коду).

#### 3.5.2. Флажок

- `input type=checkbox`: щелчок и Пробел переключают (по AUTHORING; проверено по коду: `UiControls.cs`, ветка `IsCheckbox`).
- Отмеченный рисуется квадрат с отступом внутри (`UiControls.cs`, строки 1061–1069, цвет `Accent(s, opacity)`).
- Вид по умолчанию (UA): 1em × 1em, `cursor: pointer`, отмеченный — фон `#1d3a3f`. Внутренний квадрат — цветом `accent-color` (по умолчанию `#40c8be`).
- `onchange` приходит при изменении (`UiControls.cs`, строки 772 и 795; по AUTHORING).

#### 3.5.3. Радио

- Радио с одним `name` в окне — одна группа; отмечено одно. Радио без `name` — группа из одного (по AUTHORING; `RadioGroup.cs`).
- Значение по умолчанию — `on` (`RadioGroup.ValueOf`).
- Щелчок, Enter или Пробел отмечают радио и снимают остальные (по AUTHORING).
- Tab встаёт на отмеченное радио группы; пока отмеченного нет — на первое. Стрелки вверх, влево и вниз, вправо переходят к соседу и отмечают его (по AUTHORING; (не проверено по коду: полный набор клавиш в обработчике радио)).
- `data-model`: достаточно поставить на одно радио группы. Отмечено то радио, чьё `value` равно значению модели (сравнение по тексту: `3` и `"3"` совпадают). Радио без своего `data-model` тоже следуют за моделью (`Core/Template.cs`, строки 451–460, проверено по коду).
- `onchange` приходит только новому отмеченному и только после удачной записи в модель; при неудачной записи — предупреждение в журнале и без `onchange` (по аудиту D, пункт 11; `UiControls.cs`, строки 274 и 283–284).
- Вид (UA): `input[type=radio] { width: 1em; height: 1em; padding: 0; border-radius: 50%; cursor: pointer }`; отмеченный — фон `#1d3a3f`; точка внутри — цветом `accent-color`.

#### 3.5.4. Ползунок (`input type=range`)

- Атрибуты: `min` (по умолчанию 0), `max` (100), `step` (1; `any` — без сетки), `value` (без него середина), `data-model`, `oninput` (на каждое движение), `onchange` (по отпусканию мыши и на каждую клавишу) (по AUTHORING; `UiControls.cs`, строки 742–751).
- Значение встаёт на сетку шага от `min`; `max` вне сетки недостижим (`RangeField.Snap`, как в HTML).
- Мышь: нажатие на дорожку ставит движок под курсор, дальше он идёт за мышью; клавиатуру игре не отдаёт.
- Клавиши (фокус Tab): стрелки — шаг; PageUp и PageDown — десять шагов; Home и End — края (по AUTHORING).
- Колесо ползунок не двигает: оно листает страницу (по AUTHORING; (не проверено по коду: поведение колеса над ползунком)).
- Рисует движок: дорожка цветом текста (прозрачность 22 %), часть до движка и круглый движок цветом `accent-color`. Размер задаёт `height`: движок — 4/5 высоты, дорожка — 3/10 (по AUTHORING).

#### 3.5.5. Список `select`

- `option value="…"`; `disabled` у варианта.
- Раскрывается окном на 8 строк (`DropRows = 8`, `UiControls.cs`, строка 20). Колесо над раскрытым списком листает его (`UiControls.Wheel`, строки 532–538). Стрелки и Enter выбирают (по AUTHORING).
- Внутри блока со `scale` строки списка рисуются без масштаба (раздел 4.9).
- Esc закрывает список (раздел 5.8).

#### 3.5.6. Кнопка

- Щелчок вызывает `onclick`. По щелчку фокус кнопка не берёт (раздел 5.3); Tab переводит на неё.
- Enter и Пробел на сфокусированной кнопке — (по AUTHORING; (не проверено по коду: ветка для кнопки в `UiControls.cs`)).
- `data-default` — кнопка, которую нажимает Enter в поле без `onenter` (раздел 3.5.1).
- `disabled`: не реагирует, `:disabled`. По UA `input:disabled, select:disabled, textarea:disabled` — `opacity: 0.5`, курсор `auto`.

#### 3.5.7. Редактор кода (`textarea`)

См. раздел 5.6.

### 3.6. Шаблоны и данные

Все привязки читают `Data` (объект или словарь). Шаблон **только читает** данные; записывать их может только C# (по AUTHORING; проверено по коду: `Core/Expr.cs`, в грамматике нет присваиваний).

| Разметка | Что делает | Замечания |
|---|---|---|
| `{{путь}}` в тексте и атрибутах | подставляет значение | `{{}}` в атрибутах, имена которых начинаются с `on`, не подставляется (`Core/Template.cs`, строка 145) |
| `{{путь \| формат}}` | формат `.NET`: `0`, `0.0`, `#`, `,`, `F1` | `{{x \| 000}}`, `{{v \| 0.0}}` (по AUTHORING; (не проверено по коду: полный набор форматов — это `ToString` .NET)) |
| `data-for="r in rows"` + `data-key="r.id"` | повтор элемента | с `data-key` строки с тем же ключом переиспользуются; без ключа — по номеру строки |
| `data-virtual="on"` / `"off"` | виртуальный список | внутри `overflow: auto/scroll` от 100 строк список виртуальный автоматически (`Core/Template.cs`, `AutoVirtual`); высота строк одинаковая (по AUTHORING) |
| `data-if="условие"` | элемент есть, только если условие истинно | скрытый элемент не строится и не занимает места (`Template.cs`, строки 386–392) |
| `data-class="имя: условие; имя2: условие"` | классы по условиям | запись без двоеточия — замечание (`Template.cs`, строка 132) |
| `data-disabled="условие"` | `disabled` по условию | |
| `data-model="путь"` | поле ↔ данные в обе стороны | для `input`, `textarea`, `curve`, `chart`, `gauge`; запись в модель редактора кода — не чаще раза за кадр (по AUTHORING) |
| `data-t="id"`, `data-t-title="id"`, `data-t-<атрибут>="id"` | перевод | текст по id подставляется **при чтении страницы** (`Core/Localizer.cs`); нет текста — замечание страницы, элемент остаётся как в разметке. Источник — `TextManager` игры (`Api/BaroUi.cs`, строка 44). В пакете `own/BBE_UI` папки `Localization` нет (проверено по составу пакета). Тексты пакета попадают в `TextManager` так же, как у соседних пакетов: строкой `<Text file="%ModDir%/Localization/English.xml" />` в `filelist.xml` (проверено по `own/BBE_Mods/filelist.xml` и `own/BBE_Terminal/filelist.xml`); что игра грузит их так именно для этой страницы, в игре не проверено. Прежняя фраза AUTHORING «файлы текстов пакета» исправлена 2026-11-16. Текст с `{{…}}` связывается после подстановки |

Built-in обработчики (проверено по коду: `Render/UiWindow.cs`, строки 153–156):

| Вызов в атрибуте | Действие |
|---|---|
| `close()` | закрыть окно |
| `showModal('id')` | открыть `dialog` с этим `id` |
| `closeDialog()`, `closeDialog('id')` | закрыть модальное окно (текущее или с этим `id`) |
| `focus('id')` | фокус на элемент с этим `id` |

Выражения (проверено по коду: `Core/Expr.cs`):

- Пути: `a.b[0].c`; регистр имён не важен (по AUTHORING). `.length` и `.count` для списков (`Expr.cs`, строка 178).
- Литералы: числа, строки в `'одинарных'` кавычках, `true`, `false`, `null`.
- `$index` — номер строки в `data-for` (`Expr.cs`, строка 224).
- Операторы: `+ - * / %`, сравнения `== != < <= > >=`, `&&`, `||`, `!`, скобки. Строки склеиваются через `+` (`Expr.cs`, строка 270).
- Тернарного `?:`, вызовов функций и присваиваний в грамматике не найдено (проверено по коду: `Expr.cs`).

Аргументы обработчиков — выражения из атрибута, например `onclick="craft(r.id)"`. Переменная `this` в выражении — (не проверено по коду; по AUTHORING — сам элемент).

### 3.7. События (атрибуты `on*`)

Имена, которые движок вызывает (проверено по коду: вызовы `Fire(e, "…")` и `Dispatch`):

| Атрибут | Когда приходит |
|---|---|
| `onclick` | щелчок левой кнопкой по элементу; если у элемента нет `onclick`, ищется ближайший предок с ним (`Template.Dispatch`). После перетаскивания дальше 4 px не приходит (раздел 5.2) |
| `oninput` | после каждой правки текста; у ползунка — на каждое движение; у `textarea` — один вызов за кадр |
| `onchange` | при уходе из поля, если текст изменился; у флажка — при изменении; у ползунка — по отпусканию; у радио — после удачной записи модели |
| `onenter` | Enter в текстовом поле (вместо нажатия `data-default`) |
| `onfocus`, `onblur` | получение и потеря фокуса (`UiControls.cs`, строки 179 и 235) |
| `onclose` | закрытие `data-popup` (всплывающего окна) и `dialog` (`UiControls.cs`, строки 473 и 654) |
| `onback`, `onforward` | кнопки мыши 4 и 5 и Alt+Left / Alt+Right: элемент под указателем и предки, затем фокус и предки (`Core/NavRoute.cs`; раздел 5.8а; проверено по коду) |
| `onsave` | Ctrl+S в `textarea` (`UiCodeEdit.cs`, строка 265) |
| `onpick` | щелчок по точке или столбику `chart`; индекс точки — в `data-picked`, передаётся как `$arg` (`UiCharts.cs`, строки 669–670; `onpick="pick($arg)"`) |

Замечания (проверено по коду):

- Поиск обработчика идёт от цели вверх по предкам: первый элемент с нужным атрибутом получает событие (`Core/Template.cs`, `Dispatch`, строки 682–687).
- Исключение в обработчике мыши закрывает окно и пишется в журнал (`UiWindow.Fail`). Для клавиатуры — так же (раздел 5.8; аудит D, пункт 11).
- Атрибутов `onkeydown` и `onkeyup` нет; отпускания клавиш движок не получает (по коду: поиска `keyup` в исходниках нет). Для клавиш — `data-keys` и `SetKeys` (раздел 5.3).
- Атрибутов мыши `onmousedown`, `onmouseup` и т.п. нет. Для мыши — `data-mouse` и `SetMouse` (раздел 5.1).

## 4. CSS: значения, селекторы, каскад, свойства

### 4.1. Единицы и значения

| Вид | Поддерживается | Замечания |
|---|---|---|
| `u` | да | основная единица холста (раздел 1.2) |
| `px` | да | значение как написано (раздел 1.2) |
| `em` | да | размер шрифта элемента; для `font-size` — шрифт родителя; `letter-spacing`, `word-spacing`, `text-indent`, `text-shadow` считаются у элемента, который их написал (по AUTHORING; проверено по коду: `StyleEngine.cs`, строки 1017–1019) |
| `%` | да | смысл зависит от свойства: от содержащего блока, от свободного места (`background-position`), от стороны картинки (`border-image`), от размера шрифта (`text-decoration-thickness`), от высоты прокрутки (`sticky`) |

| `rem`, `vw`, `vh`, `vmin`, `vmax`, `ch`, `ex`, `pt`, `cm`, `in` | нет | `Length.TryParse` знает только `px fr em % u` (проверено по коду: `CssValues.cs`, строка 24) |

Числа: `1.5`, `-2`, `.5` — с точкой, без запятой (проверено по коду: `float.TryParse` с `InvariantCulture`).

### 4.2. Цвета

- Именованные (проверено по коду: `CssValues.cs`, строки 60–66): `transparent`, `black`, `white`, `red`, `green` (#008000), `blue`, `yellow`, `orange`, `gray`/`grey` (#808080), `cyan`, `teal`, `magenta`, `lime`, `silver`, `navy`, `maroon`, `purple`. Регистр не важен. (AUTHORING приведён в соответствие 2026-11-16: в нём теперь все 18 имён, включая `silver`, `navy`, `maroon`, `purple`.)
- Шестнадцатеричные: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa` (проверено по коду: `TryHex`).
- Функции: `rgb(r, g, b)`, `rgba(r, g, b, a)`; каналы — числа 0–255 или проценты; альфа — 0–1 или процент; разделители — запятая или пробел, альфа через `/` (проверено по коду: `Rgba.TryParse`).
- `hsl()`, `hwb()`, `lab()`, `color-mix()` — нет (проверено по коду).
- `currentcolor` — цвет текста этого элемента (проверено по коду: по значениям по умолчанию `border-*-color`, `outline-color`, `text-decoration-color`, `text-shadow`).
- Прозрачность для переходов: из `transparent` цвет не «темнеет» — берётся цвет цели (по AUTHORING; `Core/Animation.cs`).

### 4.3. Переменные и ключевые слова

- Пользовательские свойства: `--имя: значение;`. Наследуются. Могут ссылаться друг на друга (`var(--a)` внутри `--b`).
- `var(--имя)` и `var(--имя, запасное)` подставляются рекурсивно (проверено по коду: `StyleEngine.cs`, `Replace var`, строки 1044–1060). Если переменной нет и запасного нет — объявление отбрасывается с замечанием (`StyleEngine.cs`, строка 958).
- `var()` внутри `@keyframes` не подставляется (проверено по коду: комментарий к `@keyframes`, `StyleEngine.cs`, строка 846).
- Ключевые слова `inherit`, `initial`, `unset` — поддерживаются (проверено по коду: `StyleEngine.cs`, ветки `inherit`, `initial`, `unset`).
- `!important` — поддерживается (по AUTHORING и разделу 4.7).

### 4.4. Селекторы и комбинаторы

Поддерживается (проверено по коду: `Core/CssParser.cs`, `ParseSelector`, и `Core/StyleEngine.cs`):

- Тип: `div`, `button`; `*` — любой элемент.
- Идентификатор: `#id`; класс: `.cls` (несколько классов подряд — `.a.b`).
- Атрибут: `[name]` и `[name=value]` (значение можно в кавычках).
- Комбинаторы: потомок (пробел), `>` (ребёнок), `+` (следующий брат), `~` (любой следующий брат). Их можно смешивать: `.x > .y + .z ~ li`. Два комбинатора подряд — ошибка правила (`CssParser.cs`, строка 455).
- Список через запятую: `a, b, c { … }`.

Не поддерживается (ошибка правила с замечанием):

- Операторы атрибутов `[a^=…]`, `[a$=…]`, `[a*=…]`, `[a~=…]`, `[a|=…]` (проверено по коду: `CssParser.cs`, строка 478, «only [name] and [name=value] are supported»).
- Псевдоэлементы, кроме `::before` и `::after` (`::first-line`, `::marker`, `::selection`, `::placeholder` — ошибка, проверено по коду: строка 503).
- Пространства имён, `@`-правила внутри селектора, экранирование в селекторах (не проверено по коду).

Специфичность (проверено по коду: `CssParser.cs`, подсчёт `ids`, `classes`, `tags`):

- id — 1 0 0; класс, атрибут и псевдокласс — 0 1 0; тип и псевдоэлемент — 0 0 1. Комбинаторы веса не добавляют (по AUTHORING).
- `:not(X)` — вес аргумента. `:has(X)` — вес аргумента (`CssParser.cs`, строка 516).
- Порядок: позже объявленное побеждает при равной специфичности (по AUTHORING и разделу 4.7).

| Псевдокласс | Когда истинен |
|---|---|

| `:nth-child(N)`, `:nth-child(odd)`, `:nth-child(even)` | номер среди элементов-братьев (проверено по коду: `CssParser.cs`, строки 121–131) |

Ограничения (проверено по коду):

- `:link`, `:visited`, `:empty`, `:is()`, `:where()`, `:lang()`, `:first-of-type` и остальные — ошибка правила с замечанием (`CssParser.cs`, строка 550: «pseudo-class :X is not supported»).

Производительность состояний: `:hover`, `:active`, `:focus`, `:focus-within`, `:dragging`, `:drag-over`, `:has()` перестилают только то, что правило может видеть (раздел 10, `PERF.md`).

#### Псевдоэлементы `::before` и `::after`

(по AUTHORING; проверено по коду: `CssParser.cs`, строки 496–512, `StyleEngine.cs`, `ResolveOne`, `PseudoTextKey`.)

- `.a::before { … }` рисует коробку перед содержимым элемента, `::after` — после. Старая запись `:before` и `:after` (один двоеточие) тоже принимается (комментарий в `CssParser.cs`, строка 496).
- Коробка лежит в раскладке как первый или последний ребёнок, но **не является элементом**: её нет в дереве, шаблоны, обработчики и запросы её не видят. Наведение, нажатие и мышь на коробку — это событие самого элемента; коробка своих событий не принимает.
- Один псевдоэлемент на селектор и только в конце: `.a:hover::before` — можно; `.a::before .b` и `::before::after` — ошибка.
- Коробка создаётся только при `content`, отличном от `none` и `normal`. Её стиль: `display` (по умолчанию `inline`), `position: absolute` с `top`/`left`, `background`, `border`, `border-radius`, `box-shadow`, `width`, `height`, `padding`, `margin`, `transition`. Наследуемые свойства берутся у элемента.
- Состояния элемента действуют и на коробку: `.a:hover::before { color: #f88 }`.
- `content`: строки в кавычках с CSS-экранированием (`"\201C"`), `attr(имя)` — значение атрибута, `icon(имя)` — значок Lucide (как `data-icon`, раздел 7.2; если правило не задало `font-family`, шрифт `lucide`). Части склеиваются подряд: `content: "№ " attr(data-id)`. `none` и `normal` — коробки нет. `counter()`, `counters()`, `url()` — коробки нет и одно замечание в журнале (проверено по коду: `StyleEngine.cs`, строка 757).
- Не поддерживаются: `::first-line`, `::first-letter`, `::marker`, `::selection`, `::placeholder`, `counter()`, `counters()`, `content: url(…)`.
- Пример: `own/BBE_UI/UI/pseudo_demo.html` и `pseudo_demo.css`.

| `-webkit-line-clamp` | псевдоним `line-clamp` | | |

**4.6.4a. Русская склейка (`-bbe-ru-glue`).** Проверено по коду: `Core/RuText.cs`; описание по AUTHORING. В тексте с кириллицей между двумя словами не бывает переноса строки, если:

- первое слово — предлог или союз из списка `в к с у о и а я но на за по от до из не ни во ко со об да` и `без для под над при про что как или либо ибо чем` (любой регистр; без запятой после него);
- второе — частица `же бы ли ль ж б`;
- второе — тире `—` или `–`;
- первое — число, второе — единица (`км м см мм кг г т л мл с сек мин ч шт % ₽ $ € руб г. тыс. млн` и др.);
- первое — `№`;
- первое — инициал (`А.`), второе начинается с заглавной.

Склеенная пара — один неразрываемый элемент; текст не меняется (копирование и выделение видят то, что написано). `auto`: правила включены, если ближайший `lang` у элемента или предка — `ru` или `ru-RU`, либо `lang` нигде нет; `lang="en"` и любой другой выключает. `on` включает при любом `lang`, `off` выключает.

Важно: `auto` при отсутствии `lang` **включает** склейку. Это решение владельца (аудит C, пункт 4; `docs/HANDOFF.md`, вопрос 1). Переносы русского текста во всех окнах при этом немного другие.

**4.6.4б. Тень текста.** Проверено по коду: `Core/TextShadow.cs`, `StyleEngine.cs`, строка 1257.

- Формат: `<x> <y> [<blur>] <цвет>`; цвет — в любом месте; без цвета — `currentcolor` (цвет текста этого кадра, поэтому переход цвета текста тоже меняет тень).
- Длины: `px`, `u`, `em`; `0` без единицы допустим; `em` и `u` переводятся в пиксели у элемента, который написал тень (`TextShadow.ResolveUnits`).
- Текст рисуется второй раз со сдвигом `(x, y)` цветом тени до основного текста; учитываются `opacity` блока и `scale`.
- Не анимируется (по AUTHORING; `Core/Animation.cs`, таблица свойств анимации).

Линейные градиенты (проверено по коду: `Core/Gradient.cs`; по AUTHORING):

- `linear-gradient(...)`: `to top`, `to right`, `to bottom`, `to left`, углы `0`, `90deg`, `180deg`, `270deg` (также `turn`, `rad`, `grad`); углы `to top right` и т.п. — косая линия по правилам CSS. По умолчанию `to bottom`.
- Стопы: цвета с альфой, позиции в `%`, жёсткие стопы.
- Градиент идёт по рамке блока; длина полосы — по `em`/`u` для стопов в этих единицах.

Радиальные градиенты: `radial-gradient([circle|ellipse] [closest-side|farthest-side|closest-corner|farthest-corner|<длина> [<длина>]] [at <позиция>], стопы)`. По умолчанию `ellipse farthest-corner at center`. Длины — `px`, `u`, `em`; позиция — `%`, `px`, `u`, `em` или `left/center/right/top/bottom`. Любое число стопов.

Нет: `conic-gradient`, `repeating-*`, подсказки цвета (color hints), радиус в `%` у радиального градиента. Такой слой — предупреждение один раз, и градиент блока не рисуется совсем (по AUTHORING; `Core/Gradient.cs`, строка 113).

Слои: `background-image: radial-gradient(...), linear-gradient(...)`. `url()` и `sprite()` в списке пропускаются градиентом и рисуются картинкой (проверено по коду: `Gradient.cs`, строка 122).

Скругления у градиента — в разделе 4.6.6 (углы запекаются отдельно, по каждому углу своим эллипсом; до 11 спрайтов; радиус до 96 px текстуры).

Ограничения (по AUTHORING и аудиту C): градиент длиннее 512 px текстуры растягивается сэмплером; при плавном зуме полоса и углы берутся с ближайшей ступени масштаба; не больше 64 запеканий полос, углов и областей за кадр, остальные — на следующий кадр без градиента. Вид в игре — (не проверено в игре).

Картинка фоном (`url()`, проверено по коду: `Render/Painter.cs`, `ImageCss`):

- Путь от папки страницы (`url(img/a.png)`, `url("../Images/a.png")`). Путь не может выходить за папку с `filelist.xml` (`Core/ImageLayout.cs`, `ResolvePath`). Адреса `http(s)://`, `data:`, `file:` и абсолютные пути отклоняются с замечанием. `?` и `#` в адресе отрезаются.
- Один слой. Скругления у картинки нет: углы прямые (раздел 4.6.6, ограничения).
- Файл не найден или не картинка — строка в журнале, блок без картинки.
- Картинка читается при первой отрисовке и держится в памяти; один файл — одна текстура на окно; файл перечитывается, если его сохранили (по AUTHORING; `UiImages.cs`, проверка раз в секунду).
- `sprite(вид:id)` — спрайт игры (раздел 7.3).

Поведение контура (по AUTHORING; проверено по коду: `Core/OutlineSpec.cs`, `Render/Painter.cs`):

- Контур **не занимает места**, не наследуется, снаружи рамки на `outline-offset + ширину`.
- Не обрезается собственным `overflow` блока, но обрезается `overflow` предков.
- У скруглённого блока контур скруглён (радиус блока плюс отступ и ширина).
- Соседний блок, нарисованный позже, может закрыть контур: контура нет «поверх всего контекста наложения», как в браузере.
- `:focus { outline: 2px solid …; outline-offset: 2px }` — обычный приём для полей и кнопок.

Тени и скругления (по AUTHORING и аудиту C):

- `box-shadow` и контур берут один радиус: наибольший из меньших полуосей углов. У разных углов тень и контур округлены по самому большому.
- Тень рисуется до фона; размытие — по форме блока с его радиусом; внутри `scale` тень чёткая.
- Тень, заходящая внутрь обрезки, рисуется, даже если блок чуть не доходит до края (аудит C, пункт 13).
- Под полупрозрачным блоком тень видна насквозь (браузер вырезает её под блоком). Это отличие (по AUTHORING).

Скругление и обрезка (по AUTHORING и `docs/ui/PERF.md`, раздел «Скругление по overflow»):

- `overflow: hidden` режет детей **по прямоугольнику, не по скруглению**: дети, заходящие в угол скруглённого блока, видны в квадратном углу.
- Геометрия обрезки по скруглению есть (`Core/RoundedClip.cs`), но рисование не включено: переключение цели рисования посреди кадра стирает экран (проверено по `ui_host`, `PERF.md`).
- Картинка в скруглённой карточке заходит в угол. Это то же ограничение.

- **Покрытие краёв (лейн G, 2026-11-16; в игре не проверено).** Края скруглённых блоков, колец, углов и кругов (`UiDraw.Disc`, текстуры углов) считаются аналитически: расстояние от центра пикселя до края даёт покрытие через один линейный переход шириной 1 px (`Core/Coverage.cs`, `Edge`). Прямая сторона на сетке даёт ровно 0 или 1, поэтому дуга и прямая одной ширины. Прежние 4×4 выборки и степенная поправка 0,55–0,7 убраны. Тонкие кольца 1–2 px: частично покрытые пиксели поднимаются степенями 0,8 (1 px) и 0,9 (2 px), `Coverage.ThinLift` (проверено по коду); значения выбраны расчётом, не подгонкой по снимку Chrome. Толще 2 px поправки нет; полностью покрытые и пустые пиксели не меняются. Ограничения: маски с дробным радиусом не делаются (радиус округляется до целого px, `Core/Corners.cs`, `CornerPx`); обрезка по скруглению не включена (раздел 11.1).

### 4.8. Анимации

(по AUTHORING; проверено по коду: `Core/Animation.cs`, `Core/Easing.cs`, `Core/CssParser.cs` (`@keyframes`)).

Движок считает анимации сам, на каждом кадре. Из кода ничего вызывать не нужно.

| Группа | Свойства | Как |
|---|---|---|
| прозрачность | `opacity` | число |

| тень | `box-shadow` | сдвиг, размытие, разброс и цвет; только в `transition`, не в `@keyframes` (по AUTHORING) |

**`transition`.** `transition: opacity 0.15s ease-out, background-color 0.15s;` или `transition: all 0.2s`.

- Плавности: `linear`, `ease` (по умолчанию), `ease-in`, `ease-out`, `ease-in-out`, `step-start`, `step-end`, `cubic-bezier(x1, y1, x2, y2)`, `steps(n)` (проверено по коду: `Easing.cs`).
- `transition: all` — все свойства из таблицы выше, включая длины (проверено по коду: `StartTransitions`, ветка `all`). Из-за длин `all` может запускать раскладку; для блоков списка лучше явный список.
- Переход запускает тот стиль, в который блок переходит (как в CSS): пишите `transition` в обычном правиле блока, а не только в `:hover`, если нужны оба направления.
- Новый блок появляется сразу, без перехода.
- Прерванный переход начинается с того значения, где остановился.
- Длительности, задержки — `s` и `ms` (по AUTHORING; (не проверено по коду: разбор `ms`)).

Длины и `layout-fps`: длины двигают раскладку блока. Значения берутся по сетке времени `layout-fps` (по умолчанию 30 раз в секунду), раскладка запускается только когда значение сдвинулось. Держите такие анимации на небольших блоках и коротких (до 0,3 с).

**`transition: layout`** — плавная раскладка без пересчёта по кадрам (проверено по коду: `Animation.cs`, строка 120 — `spec.Flip`):

```css
.row { transition: layout 0.25s ease-out; }
.panel { transition: layout 0.2s ease-out, opacity 0.15s; }
```

- Анимируется положение блока относительно родителя (блок и всё внутри едут вместе) и размер (блок рисуется в промежуточном размере; содержимое — в конечной раскладке, обрезается рамкой; текст не перестраивается по ходу).
- Включите `layout` у блока, который меняет размер, и у соседей, которые сдвигаются (обычно у всех строк списка). Блок без `layout` перескакивает сразу.
- Кадр стоит как обычная отрисовка: пересчёта раскладки нет.
- Прерванное движение продолжается с того места, где блок нарисован.
- Новые блоки не анимируются (для появления — `opacity` и `@keyframes`). Первая раскладка окна и смена размера экрана тоже без перехода.
- `transition: all` блоки раскладки не включает; `layout` пишется явно.
- Не вешайте `layout` на строки длинного прокручиваемого списка с `data-for` (виртуального): строки пересоздаются и могут ехать на новое место.
- В браузерном предпросмотре движение не видно: блоки перескакивают сразу.

**`animation` и `@keyframes`:**

```css
@keyframes rise { from { opacity: 0; translate: 0 12u } to { opacity: 1; translate: 0 0 } }
.panel { animation: rise 0.25s ease-out both; }
```

- Остановки: `from`, `to`, `NN%`. Сокращения вроде `margin` раскрываются; `var()` не подставляется (проверено по коду: `StyleEngine.cs`, строка 846).
- Если `from` или `to` не заданы, берётся значение из обычного стиля блока.
- Повторы: число или `infinite`. Направление: `normal`, `reverse`, `alternate`, `alternate-reverse`. `fill`: `none`, `forwards`, `backwards`, `both`. Слова `running` и `paused` в сокращении `animation` принимаются и ничего не делают; отдельного свойства `animation-play-state` нет (проверено по коду: `Animation.cs`, строка 270; `Initial`).
- Анимация стартует, когда блок появился (страница открылась, пришла строка списка, `data-if` включил блок). Начинается заново, если у блока сменилось значение `animation`. Скрытый `data-if` блок при показе стартует снова.
- Сокращение `animation: имя время [плавность] [задержка] [повторы|infinite] [направление] [fill]`; по частям — `animation-name`, `animation-duration`, `animation-timing-function`, `animation-delay`, `animation-iteration-count`, `animation-direction`, `animation-fill-mode`.
- Пример лесенки: `.row:nth-child(2) { animation-delay: 0.05s }`.

**Печатная машинка.** `typewriter: 60` у блока с текстом показывает текст по 60 знаков в секунду. Перенос строк уже сделан на полном тексте, текст не прыгает. Окно сообщает `IsTyping`; по клавише подтверждения хозяин вызывает `SkipTyping()` (проверено по коду: `UiWindow.IsTyping`, `SkipTyping`). Начинается заново, когда текст изменился.

**Выключатель.** `baroui anim off` выключает все анимации окон: изменения происходят сразу, текст виден целиком (раздел 9). Время анимаций — по часам окна, а не по часам мира; (по AUTHORING: на паузе мира анимации продолжаются; `Timing.TotalTime`).

Чего нет: `transition` для `font-size` (каждый размер — новый шрифт); анимация `border-radius`; анимация `text-shadow`; `@keyframes` с `box-shadow`; `animation-play-state`; `animation-composition`; `transition-behavior`.

### 4.9. Масштаб, сдвиг и координаты

(по AUTHORING; проверено по коду: `Core/UiTransform.cs`, `Core/ScreenMap.cs`, `Render/Painter.cs`, `EnterScale`/`LeaveScale`.)

**`translate`** — сдвиг в пикселях экрана при рисовании; раскладка не меняется; блок и всё внутри едут вместе; зона мыши тоже.

**`scale`** — масштаб блока и всего внутри него:

- Центр масштаба — левый верхний угол рамки самого блока **после** его `translate`: точка `p` внутри блока рисуется в `угол + translate + N·(p − угол)`.
- Вложенные `scale` перемножаются. Мышь, обрезка `overflow` и текст согласованы с картинкой; текст берёт шрифт нужного размера и остаётся чётким.
- Блок вне экрана не рисуется, как и без масштаба.
- **Это не как в браузере.** В браузере центр масштаба — посередине. Для браузерного предпросмотра пишите рядом `transform-origin: 0 0`.

Работает внутри блока со `scale` (по AUTHORING): фон, рамки, скругления, текст (чёткий, до 160 px на экране, дальше растягивается), кнопки, флажки, ползунки `range`, поля ввода (каретка и выделение мышью), `textarea`, `title`-подсказка, наведение, `:active`, клики, `overflow: hidden` и прокручиваемые блоки, `item`, `progress`, `canvas` (обратный вызов рисует в тех же пикселях, результат масштабируется вместе с блоком; `SetCanvasMouse` отдаёт позиции в этих же пикселях).

Не работает внутри блока со `scale` (по AUTHORING; то, что не сделано, не притворяется рабочим):

- `slot` (ячейки инвентаря): игра рисует их по экранному прямоугольнику; не рисуются, предупреждение один раз на строку шаблона.
- `select`: строки списка рисуются без масштаба; список открывается поверх экрана у правильного места, с шириной и высотой строки, как у поля на экране; шрифт строк — обычного размера.
- `dialog`: открывается поверх экрана без масштаба, без `translate` и прокрутки предков; предупреждение один раз.
- Синтетический курсив у шрифта без своего курсива (JetBrains Mono, Caveat) растягивается матрицей и выглядит нечётко; у PT Serif курсив настоящий.
- Обратный вызов `<canvas>`, который сам читает мышь (`PlayerInput`) или перезапускает пакет, считает в экранных пикселях: берите `SetCanvasMouse`.
- `BoxOf(e)` отдаёт прямоугольник раскладки без `translate`, без сдвига анимации, без прокрутки и без `scale`. Место на экране даёт **`ScreenRect(e)`** (`Render/UiWindow.cs`, строка 487): оно учитывает `translate` (CSS или `SetTranslate`), сдвиг анимации раскладки элемента и предков, прокрутку и вложенные `scale` в том же порядке, что рисует `Painter` (`Core/ScreenMap.cs`). Так же считаются каретка и прямоугольник IME поля, подсказка `title`, список `select`, полоса прокрутки и зона мыши ползунка.

**`position: sticky`** (по AUTHORING и `docs/ui/PERF.md`; проверено по коду: `ScreenMap.StickyOffset`, `LayoutBox.Sticky`):

- Блок держится у `top` или `bottom` ближайшего прокручиваемого предка (`overflow-y` не `visible`) и не выходит за свой родительский блок.
- Раскладка не меняется: двигаются рисование и мышь (одна формула в `ScreenMap`).
- Без прокручиваемого предка блок не двигается.
- Значения `top`/`bottom` — `px`, `u`, `em`, `%` от высоты прокрутки.
- Пример: `#head { position: sticky; top: 0 }` в прокручиваемом блоке.
- Не сделано: `left`/`right` (горизонтальный sticky); sticky внутри элементов с `transform: scale` (сдвиг считается в неизменённых координатах) (`PERF.md`).

**`SetTranslate` и `SetScale` из C#** (раздел 8): число заменяет CSS-значение этого элемента (как `element.style`), вместе с переходом и анимацией; без перестиливания и без пересчёта раскладки. `NaN` и бесконечность игнорируются; на копию (`Clone`) число не переносится. Для всего, что движется каждый кадр, ставьте `data-key` у строк `data-for`: без ключа число живёт на позиции строки и при вставке или перестановке уедет.

## 5. Ввод: мышь, фокус, клавиши, меню, перетаскивание, файлы

Общие факты (проверено по коду, `Core/PointerRouter.cs`, `Core/KeyRouter.cs`, `Core/FocusOrder.cs`, `Core/Popup.cs`, `Core/DragDrop.cs`, `Core/FileInput.cs`, `Render/UiControls.cs`, `Render/UiWindow.cs`): ввод окна идёт через один маршрутизатор на окно; игровые вызовы (`PlayerInput`, `DebugConsole`, `PauseMenuPrefix`) только передают события внутрь.

### 5.1. Мышь на элементах: `data-mouse`, `SetMouse`

Элемент получает события мыши, если у него есть `data-mouse="имя"`. Обработчик владелец ставит по имени:

```csharp
window.SetMouse("card", e => { … });            // Func<UiMouseEvent, bool>
window.SetMouse("card", e => { … });            // Action<UiMouseEvent>: отвечает true всегда
window.ClearMouse("card");                       // снять; захват, который он держал, кончится Cancel
```

(проверено по коду: `Render/UiWindow.cs`, строки 379–390.)

`data-mouse-events="down up click dblclick contextmenu wheel enter leave move hover"` — какие события нужны. Без атрибута приходят все, кроме `move` и `hover` (`PointerRouter.cs`, строки 462–474; проверено по коду).

Виды (`UiMouseKind`, проверено по коду: `Core/PointerEvents.cs`): `Down`, `Up`, `Move`, `Enter`, `Leave`, `Wheel`, `Click`, `DoubleClick`, `ContextMenu`, `Hover`, `Cancel`. Что именно шлёт `Hover` — (не проверено по коду).

Поля `UiMouseEvent` (проверено по коду):

| Поле | Смысл |
|---|---|
| `Kind` | вид события |
| `Button`, `Held` | кнопка этого события; все зажатые кнопки |
| `X`, `Y` | экран |
| `LocalX`, `LocalY` | точка в содержимом элемента `Current`, в его пикселях |
| `Width`, `Height` | размер содержимого `Current` |
| `Target` | самый глубокий элемент под указателем |
| `Under` | элемент под указателем во время захвата или перетаскивания (раздел 5.1, ниже); иначе `null` |
| `Current` | чей обработчик сейчас вызван |
| `Path` | цепочка элементов от `Target` вверх |
| `Up(attr)` | ближайший предок с атрибутом `attr` |
| `Data(name)` | значение `data-<name>` ближайшего элемента от `Target` |
| `Captured` | событие идёт держателю захвата |
| `Inside` | указатель над элементом |
| `Dragged` | был сдвиг дальше порога |
| `ClickCount` | 1, 2, 3 — для `Click`/`DoubleClick` |
| `StartX`, `StartY` | точка начала нажатия |
| `Wheel` | щелчки колеса |
| `Ctrl`, `Shift`, `Alt` | клавиши-модификаторы (поле `Mods`) |
| `Related` | для `Enter`/`Leave` — другой элемент |
| `Time` | секунды |
| `ToLocal(el, out x, out y)` | точка в системе `el` |
| `AsCanvas()` | то же событие в виде `CanvasMouseEvent` |
| `Capture()` | захватить мышь вручную |

Правила:

- **Всплытие.** Событие начинается с самого глубокого элемента под указателем и идёт вверх по предкам с `data-mouse`. `true` останавливает всплытие. На `Down` `true` ещё и **берёт захват**: `Move`, `Up` и `Wheel` идут держателю везде (и вне окна), пока не отпущены все его кнопки.
- **`Esc`** отменяет захват: держатель получает `Cancel`. Остальное на этом нажатии не закрывается.
- **`Enter` и `Leave`** не всплывают: каждый вошедший элемент получает своё событие. Предки с `data-mouse` получают `Enter`/`Leave`, даже когда указатель над холстом (`CanvasMouse`).
- **`Move`** приходит только тем, у кого в `data-mouse-events` есть `move`, и всегда держателю захвата.
- **`Click`** (и `DoubleClick`, `ContextMenu` для правой кнопки) приходит, когда кнопка отпущена на элементе (или внутри него) там же, где была нажата, и без перетаскивания дальше порога (раздел 5.2).
- **Захват и подсказки.** Пока мышь захвачена или несётся перетаскивание, `:hover` и подсказки `title` стоят на месте (по AUTHORING).
- **`Under`.** Элемент под указателем при захвате или перетаскивании. Держатель захвата и призрак перетаскиваемого элемента при проверке попадания сдвигаются в сторону, поэтому не учитываются; `pointer-events: none` пропускается. Вне захвата и перетаскивания `Under = null`. `Target` не меняется: это держатель захвата или элемент под призраком (по AUTHORING; `UiMouseEvent.Under` добавлен 2026-11-15, аудит полосы C).
- **Не сделано:** сахар `onmousedown="…"` в разметке.

### 5.2. Порог перетаскивания и `click`

- Порог — 4 px (`PointerRouter.DragThreshold = 4f`, `PointerRouter.cs`, строка 17).
- `Click` с `data-mouse` не приходит, если указатель сдвинулся дальше порога между нажатием и отпусканием. Карточку, которую протащили, не считают нажатой (по AUTHORING).
- `onclick` (старый атрибут) — **отдельное** событие, он не зависит от `data-mouse` и приходит, даже если элемент протащили: достаточно отпустить его там же, где нажали (по AUTHORING, раздел «Мышь на элементах»). Правило «после сдвига щелчка нет» к `onclick` не относится.
- Правый щелчок `ContextMenu` приходит при сдвиге не больше порога (`PopupRules.ContextCarrier`).

### 5.3. Фокус, Tab и клавиши блоков: `tabindex`, `data-keys`, `SetKeys`

**Фокус по щелчку.**

- Нажатие на элемент (или на то, что внутри него) с явным `tabindex` — любым числом, включая `-1` — отдаёт ему клавиатуру. Персонаж при этом не управляется, как у текстового поля.
- Поля ввода и редактор кода берут фокус по щелчку сами (раздел 3.5).
- Кнопки, флажки, радио, ползунки и списки **без** `tabindex` фокус по щелчку **не берут** — это сделано нарочно: клик по кнопке не должен останавливать персонажа. Они берут клавиатуру только по Tab. Явный `tabindex` включает фокус и по клику.
- Кнопка внутри блока с `tabindex` по клику отдаёт фокус ближайшему предку с `tabindex`; клавиши идут блоку (по AUTHORING).

**Порядок Tab** (`Core/FocusOrder.cs`, проверено по коду):

1. Сначала элементы с положительным `tabindex` по возрастанию (при равных — по порядку документа).
2. Потом `tabindex="0"`, поля, кнопки и т.п. в порядке документа.
3. `tabindex="-1"` пропускается Tab, но фокусируется кликом и из кода (`focus('id')`).
4. Shift+Tab идёт назад, по кругу. Список стопов собирается заново на каждое нажатие; смена `tabindex` без раскладки заметна сразу.
5. Пока открыто всплывающее окно (`data-popup`), Tab и Shift+Tab ходят по стопам внутри него по кругу и на страницу не уходят (раздел 5.9).

**Клавиши блоку.** `data-keys` перечисляет клавиши, `data-key-name` даёт имя обработчику:

```html
<div tabindex="0" data-keys="Enter Escape ArrowUp ArrowDown" data-key-name="list">…</div>
```

```csharp
window.SetKeys("list", e => { /* e.Key, e.Ctrl, e.Shift, e.Alt, e.Target, e.Current */ return true; });
window.SetKeys("list", e => { … });   // Action<UiKeyEvent>: отвечает true всегда
window.ClearKeys("list");
```

(проверено по коду: `Render/UiWindow.cs`, строки 407–414; `Core/KeyRouter.cs`.)

Имена в `data-keys` (`KeyRouter.Parse`, проверено по коду; регистр не важен):

| Имя | Клавиша | Имя | Клавиша |
|---|---|---|---|
| `Enter` (`return`) | Enter | `ArrowUp` (`Up`) | стрелка вверх |
| `Space` | Пробел | `ArrowDown` (`Down`) | стрелка вниз |
| `Escape` (`Esc`) | Esc | `ArrowLeft` (`Left`) | стрелка влево |
| `Delete` (`Del`) | Delete | `ArrowRight` (`Right`) | стрелка вправо |
| `Backspace` (`back`) | Backspace | `Home`, `End`, `PageUp`, `PageDown`, `Tab` | |

Событие `UiKeyEvent` (проверено по коду: `Core/KeyRouter.cs`): `Key` (`UiKey`), `Ctrl`, `Shift`, `Alt`, `Target` (элемент в фокусе), `Current` (чей `data-keys` сработал).

Правила:

- Нажатие идёт от элемента в фокусе вверх по предкам, которые просили эту клавишу. `true` останавливает всплытие и **отменяет действие по умолчанию** (Пробел на флажке, переход фокуса по Tab, закрытие по Esc).
- **Клавиши правки текстового поля мимо `data-keys` не попадают** (`KeyRouter.EditsText`, проверено по коду): Delete, Backspace, Left, Right, Home, End — всегда полю; в `textarea` ещё Enter, Up, Down, PageUp, PageDown; в числовом поле Up и Down (шаг). Остальные клавиши (Esc, Tab, Пробел, Enter в однострочном поле) сначала идут в `data-keys`.
- **Только при фокусе.** Клавиши окну приходят, пока какой-то его элемент в фокусе — так устроена игра: клавиатуру берёт один подписчик, и персонаж не должен терять управление, пока ничего не выбрано (по AUTHORING). Без фокуса блок клавиш не получит. Для карты и списков дайте корню `tabindex="0"` (или `-1`).
- Отпускания клавиш (`keyup`) нет.

Мышь и клавиши в одном блоке: клавиатурный фокус и мышь независимы; клик по элементу без `tabindex` фокус не меняет (раздел 5.3, выше).

### 5.4. Мышь на `<canvas>`

`Window.SetCanvasMouse("pad", e => { … })` — обработчик мыши холста. Рисование по-прежнему `SetCanvas`; мышь можно подключить и без рисования (по AUTHORING; `Render/UiCanvasInput.cs`, `Core/CanvasMouse.cs`).

| `e.Kind` (`CanvasMouseKind`) | Когда |
|---|---|
| `Move` | указатель двигается над холстом (первое — вход); во время перетаскивания — где угодно на экране |
| `Down` / `Up` | кнопка нажата / отпущена на холсте (`e.Button`: `Left`, `Right`, `Middle`; `e.Left`, `e.Right`, `e.Middle`) |
| `Wheel` | колесо над холстом или во время перетаскивания; `e.Wheel` — щелчки, вверх положительно |
| `Leave` | указатель ушёл с холста без нажатых кнопок (снять подсветку) |
| `Cancel` | перетаскивание отобрано: окно закрылось, холст пропал или его накрыл диалог; `Up` не придёт |

Поля `CanvasMouseEvent`: `X`, `Y` — пиксели от левого верхнего угла **содержимого** холста (те же, что `Rectangle` в `SetCanvas`; во время перетаскивания могут выходить за `0..Width`, `0..Height`); `Width`, `Height`; `Ctrl`, `Shift`, `Alt`; `Held`; `Captured`; `Inside`; `Time`.

- **Захват.** Кнопка, нажатая на холсте, при `true` от обработчика держит мышь: `Move`, `Up`, `Wheel` идут холсту, пока не отпущены все такие кнопки — и вне холста, и вне окна. Пока идёт перетаскивание, мышь всего экрана принадлежит окну; персонаж не управляется. Вторая кнопка, нажатая во время перетаскивания, присоединяется к нему.
- **Ответ** (`Func<CanvasMouseEvent, bool>`): для `Down` `true` — нажатие принято (начинается перетаскивание), `false` — холст его не берёт; для `Wheel` `true` — колесо использовано, `false` — страница под холстом прокручивается. Перегрузка `Action<CanvasMouseEvent>` отвечает `true` всегда.
- `ClearCanvasMouse(id)` снимает обработчик (перетаскивание кончается `Cancel`).
- **Двойное нажатие считает владелец.** `ClickCounter.Count(e)` даёт 1, 2, 3 (и снова 1) по времени (`Interval = 0.4` с) и месту (`Distance = 6` px) подряд идущих `Down` одной кнопки (`CanvasMouse.cs`, строки 180–181).
- Холст принимает мышь только в своих границах; вне их игра получает мышь как раньше. `cursor` не меняется. Клавиатуру холст не получает: клавиши карты читает владелец через `PlayerInput`.
- Ошибка в обработчике снимает его и пишет строку в журнал; окно не закрывается (по AUTHORING).

```csharp
Window.SetCanvas("map", Draw);
var clicks = new ClickCounter();
Window.SetCanvasMouse("map", e =>
{
    switch (e.Kind)
    {
        case CanvasMouseKind.Down when e.Left: if (clicks.Count(e) == 2) { Open(NodeAt(e.X, e.Y)); } else { Grab(e.X, e.Y); } return true;
        case CanvasMouseKind.Move when e.Captured: Drag(e.X, e.Y); return true;
        case CanvasMouseKind.Wheel: Zoom(e.Wheel, e.X, e.Y); return true;
    }
    return true;
});
```

**Сдвиг и масштаб числами** (`SetTranslate`, `SetScale`) — для всего, что движется каждый кадр; см. раздел 4.9 и 8.

### 5.5. Модальное окно `dialog`

- `<dialog id="filters" closedby="any">…</dialog>`: по умолчанию `display: none`; при открытии (`showModal('filters')` или `Window.ShowModal`) — block, поверх страницы (`z-index: 1000`) (проверено по коду: UA, `Render/UiControls.cs`, `ShowModal`).
- Без `top`/`left`/`right`/`bottom` — по центру. С ними — от ближайшего `position: relative` предка (по AUTHORING).
- `closedby="any"` — нажатие мимо окна закрывает его (`UiControls.cs`, строки 361–363; проверено по коду).
- Подложка: нажатие вне диалога не доходит до игры и страницы под ним (`UiControls.HitOverlay`, проверено по коду). `dialog` открыт — ввод уходит ему.
- `Esc` закрывает верхний диалог (раздел 5.8).
- `closeDialog()` и `closeDialog('id')` (встроенные) и `Window.CloseDialog(id?)` закрывают диалог; `onclose` срабатывает (`UiControls.cs`, строка 654).
- Открытие `dialog` кодом закрывает всплывающее окно (по AUTHORING).
- `autofocus` внутри открытого диалога берёт фокус при открытии. Фокус внутри открытого меню `data-popup` `autofocus` не отбирает (аудит D, пункт 3).
- Внутри блока со `scale` диалог открывается без масштаба, без `translate` и прокрутки предков (по AUTHORING; раздел 4.9).

### 5.6. Редактор кода: `<textarea>`

Многострочный редактор, рисует движок (по AUTHORING; `Render/UiCodeEdit.cs`, `Core/CodeEdit.cs`, `Core/CodeLexer.cs`).

```html
<textarea id="code" data-lang="xml" data-model="text" oninput="edited()" onsave="save()" tabsize="4" placeholder="Пусто"></textarea>
```

Текст — `value`: содержимое тега (как в HTML, первый перенос не считается), атрибут `value`, `data-model` (в обе стороны; запись в модель — не чаще раза за кадр) или `Window.GetCodeEdit("code").SetText(…)`.

| Атрибут | Что делает |
|---|---|
| `data-lang` | `xml`, `lua`, `cs` (или имя файла, `x.xml`) — подсветка; без него текст без цветов |
| `data-model`, `value`, `placeholder`, `readonly`, `disabled` | как у `input` |
| `tabsize` | ширина табуляции в знаках (по умолчанию 4; допустимо 1–16) |
| `data-tabs="tab"` | Tab пишет знак табуляции, а не пробелы |
| `data-autoindent="off"` | Enter не копирует отступ |
| `data-gutter="off"` | без номеров строк |
| `oninput` | после правки (один вызов на кадр) |
| `onchange` | при уходе из редактора, если текст изменился с момента входа (`UiCodeEdit.cs`, строка 199) |
| `onsave` | Ctrl+S (`UiCodeEdit.cs`, строка 265) |

- **Размер и вид.** Без CSS: `30em × 12em`, рамка, `overflow: hidden` (прокрутка своя). Шрифт — **моноширинный** (по умолчанию `font-family: mono`): ширина знака измеряется один раз, по ней считаются колонки, каретка и мышь. Высота строки — `line-height`. Переноса строк нет: длинная строка прокручивается вбок (Shift+колесо, полоса снизу).
- **Цвета** — пользовательские свойства, наследуются: `--code-keyword`, `--code-type`, `--code-constant`, `--code-string`, `--code-number`, `--code-comment`, `--code-punct`, `--code-tag`, `--code-attr`, `--code-entity`, `--code-directive`, `--code-gutter`, `--code-line` (строка с кареткой), `--code-selection`. Простой текст — `color`, каретка — `caret-color`.
- **Клавиши.** Стрелки; Ctrl+стрелки — по слову; Home — первый знак строки, ещё раз — начало; End; Ctrl+Home/End; PageUp/PageDown; Shift со всем этим — выделение. Tab — до следующего стопа; с выделением — отступ строкам; Shift+Tab — убрать отступ. Ctrl+Tab уходит к следующему полю. Backspace в отступе откатывает на стоп. Enter копирует отступ, после `{ ( [` — на уровень глубже, между `{}` ставит `}` на отдельную строку. Ctrl+A, C, X, V. Ctrl+Z — отмена, Ctrl+Y и Ctrl+Shift+Z — возврат (до 1000 шагов; печать и удаление по одному знаку — один шаг).
- **Мышь.** Клик — каретка; протягивание — выделение (за краем прокручивает); двойной клик — слово; тройной — строка; клик по номеру строки — строка. Полосы прокрутки тянутся; клик по дорожке прыгает; колесо — 3 строки.
- **Тысячи строк.** Рисуются только видимые строки; текст хранится по строкам; правка трогает только их. Подсветка считается по требованию, построчно, с состоянием на конец строки; после правки пересчитывается то, что смотрят. Замеры (`tools/ui_test`, не в игре): 20 000 строк — загрузка 3 мс; 200 нажатий в середине текста — 0,1 мс; подсветка нижних строк после правки наверху — 6–8 мс один раз (по AUTHORING).
- **Окончания строк.** Модель помнит окончание файла (`CRLF` или `LF`, по большинству) и пишет его обратно; смешанный текст выравнивается по большинству (по AUTHORING).
- **Из кода.** `Window.GetCodeEdit("code")` — модель `CodeEdit` (по AUTHORING): `Text`, `Caret`, `Anchor`, `GoTo`, `Select`, `Replace(от, до, текст)`, `Undo`, `Redo`, `LineCount`, `Line(i)`. Её правки доходят до `value`, модели и `oninput` на следующем кадре. `Window.RevealCaret(id)` — показать каретку.
- **Подсветка** простая, построчная, не разбор: XML (теги, атрибуты, значения, сущности, комментарии, CDATA, `<?…?>`), Lua (слова, длинные `--[[ ]]` и `[==[ ]==]`, числа), C# (слова и встроенные типы, `@"…"`, `"""…"""`, `/* */`, `#region`; строка с `$` — одним куском, скобки внутри не разбираются) (по AUTHORING; `CodeLexer.cs`).
- Отдельно можно вызвать `CodeLexer.Scan(язык, строка, состояние, список)` (по AUTHORING).

### 5.7. Файлы: перетаскивание из Проводника и Ctrl+V

В игре нет диалога выбора файла, поэтому два пути: **перетащить файл** на окно игры и **вставить** из буфера (по AUTHORING; `Render/UiFileInput.cs`, `Core/FileInput.cs`).

```csharp
Window.SetFileInput("sprite", f => { Load(f.Path ?? SaveImage(f)); return true; }, accept: ".png,.jpg");
```

```html
<div id="sprite" tabindex="0">Перетащите файл сюда или нажмите здесь и Ctrl+V</div>
```

- Цель — блок с `id`. `accept`: расширения (`.png,.jpg`), `image/*` или `null` (любой файл).
- Обработчик получает `UiFileInput`: `Source` (`Drop`, `PasteFile`, `PastePath`, `PasteImage`), `Path` (у вставленной картинки `null`), `ImageData` (байты PNG; если в буфере был только битмап — BMP), `Extension`, `IsImage`, `Name`, `ReadBytes()`, `Target`, `Position`.
- Ответ `false` отдаёт файл следующей цели (предку). `true` — принял.
- **Перетаскивание.** Игра получает от SDL событие `FileDropped` (путь). Окно берёт файл, если под указателем в момент падения блок-цель этого окна или потомок. Окно, у которого есть цели и которое накрыло точку, забирает файл у окон под ним. Верхнее окно — новейшее показанное.
- **Вставка.** Цель получает фокус по клику и по Tab (`tabindex="0"`). Ctrl+V читает буфер в порядке: файлы, скопированные в Проводнике (`CF_HDROP`); картинка (формат `PNG` или битмап `CF_DIB`, например снимок экрана); текст с путём (в кавычках от «Копировать как путь», строка на файл, `file:///…`). Берётся то, что подходит под `accept`.
- **Нет:** подсветки цели во время перетаскивания (SDL не присылает событий, пока файл в руке); точки падения от SDL (берётся место мыши в момент падения); перетаскивания из окна в Проводник; нескольких файлов за раз у одной цели (каждый приходит отдельным вызовом).
- **Ограничение Windows.** Если игра запущена от администратора, а Проводник нет, система не отдаёт ей перетаскиваемые файлы. Буфер работает всегда (по AUTHORING).
- `Window.Images.Add(ключ, байты)` кладёт вставленную картинку в память окна (раздел 6).

### 5.8. Esc

Esc приходит из перехвата игры (`BaroUi.PauseMenuPrefix`, `Api/BaroUi.cs`, строки 52 и 186; проверено по коду).

- Esc получает **самое верхнее** окно на экране: последнее в списке окон, которое открыто и показано за последние 0,5 с. Окно, оставленное открытым там, где оно не рисуется, Esc не забирает.
- Меню игры открывается, только когда на экране нет открытых свободных окон.
- Внутри окна Esc обрабатывается по цепочке (по AUTHORING; аудит D, пункт 7):
  1. отмена захвата мыши (перетаскивание);
  2. всплывающее окно (`data-popup`); если в нём раскрыт `select`, Esc закрывает меню целиком;
  3. `data-keys` элемента в фокусе (если там есть `Escape`);
  4. раскрытый список `select`;
  5. модальный `dialog`;
  6. окно страницы (`onclose`, закрытие).
- Если обработчик закрыл окно, цепочка на этом заканчивается (проверяется `IsOpen`, аудит D, пункт 7).
- Шаг назад самого вида: `BaroUiView.OnEscape()` (по умолчанию `false`) вызывается после пунктов 1–5 и **до** события `Escape` и закрытия окна. `true` — вид сам сделал шаг назад, окно остаётся; `false` — окно закрывается (`Api/BaroUiView.cs`, `Render/UiWindow.cs`, `OnEscape`; проверено по коду). Хуки доступны любому виду; менеджер модов может ими пользоваться, но его кода в движке нет.

### 5.8а. Боковые кнопки мыши 4 и 5, Alt+стрелки

Кнопки 4 (назад) и 5 (вперёд) и Alt+Left / Alt+Right обрабатывает `BaroUi.NavigateByInput` (`Api/BaroUi.cs`) раз в кадр из `AddWindowsPrefix` (проверено по коду; **не проверено в игре**).

- Кнопка 4 / 5 идёт верхнему окну, которое под указателем (`ElementAt`). Alt+стрелка идёт самому верхнему окну на экране, как Esc.
- Окно сначала ищет атрибут `onback` / `onforward`: элемент под указателем и его предки, затем элемент в фокусе и его предки (`Core/NavRoute.cs`, `NavRoute.Target`). Найденный обработчик вызывается через `Template.Dispatch`, как `onclick`. Потом вызывается `BaroUiView.OnBack()` / `OnForward()` (`UiWindow.Navigate`).
- Если окно ответило `true`, боковая кнопка этого кадра игре не передаётся: Harmony-префикс на `PlayerInput.Mouse4ButtonClicked` / `Mouse5ButtonClicked` отвечает `false` до конца кадра (`SideBackPrefix`, `SideForwardPrefix`). Кнопка при указателе вне окон остаётся игровой.
- Ограничения: боковые кнопки не доходят до `data-mouse` (`MouseButtons` и `UiMouseEvent` кнопок 4 и 5 не содержат); Alt+стрелку поле в фокусе не отбирает; если игра прочла кнопку раньше окна в том же кадре, подавления не будет (**не проверено в игре**).
- История «назад / вперёд» (разделы, уровни) в движке не ведётся: это дело окна. Менеджер модов может вернуть `true` из `OnBack` / `OnForward` и сам решать, что назад (кода менеджера в движке нет).
- Исключение в клавиатурном обработчике пишется в журнал и закрывает окно, как при ошибке мыши (`UiWindow.Fail`; аудит D, пункт 11). Что будет с исключениями диспетчера клавиш игры после `Fail` — (не проверено в игре).

### 5.9. Всплывающие окна и контекстное меню: `data-popup`, `data-contextmenu`, `ShowPopup`

```html
<div class="menu" data-popup id="cardMenu" style="width: 160px">
  <button onclick="rename()">Переименовать</button>
  <button data-item onclick="remove()">Удалить</button>
  <button data-keep-open onclick="pin()">Закрепить</button>
</div>
<div class="card" data-contextmenu="cardMenu">…</div>
```

- Блок с `data-popup` скрыт, пока его не показали: правило движка со `!important` (`PopupPlace.Css`: `[data-popup]:not([open]) { display: none !important }`) — `#cardMenu { display: flex }` его не откроет. Открытый лежит `position: absolute` над страницей (`z-index` задан в той же строке `PopupPlace.Css`). Задайте ширину: ширина по содержимому считается от родителя (по AUTHORING).
- `Window.ShowPopup(id, screenX, screenY, anchor = null)` — у точки (контекстное меню); `anchor` — элемент, для которого открыли (его отдаёт `Window.PopupAnchor`).
- `Window.ShowPopup(id, anchor, "below")` — у элемента: `below` (под), `above` (над), `right` (справа), `left` (слева) от `ScreenRect(anchor)`.
- Не помещается — переворот на другую сторону, потом сдвиг внутрь экрана (у точки — влево и вверх от курсора). Расчёт — `Core/Popup.cs`, `PopupPlace` (проверено по коду).
- `Window.ClosePopup(id = null)`, `Window.IsPopupOpen(id)`, событие `Window.PopupClosed(popup, reason)` и атрибут `onclose` у блока.
- Причины закрытия (`PopupCloseReason`, проверено по коду: `Core/Popup.cs`, строка 7): `Outside` (нажатие мимо), `Escape`, `Chosen` (выбран пункт), `Code` (`ClosePopup`, окно удалили `data-if`, открыто модальное окно), `Replaced` (открыли другое).
- Одно всплывающее окно за раз: открытие второго закрывает первое (`Replaced`). Открытое повторно просто переезжает. Вложенных подменю нет.
- **Нажатие мимо.** Левая кнопка закрывает окно и **не доходит** до страницы (ни клика по тому, что под ним, ни смены фокуса). Правая закрывает окно и проходит дальше, поэтому на другой карточке сразу откроется её меню. Нажатие в само окно работает как обычно. Клик по полю и тексту окна его не закрывает (по AUTHORING).
- **Пункт** — `button`, `a` с `onclick`, элемент с `data-item` или любой элемент с `onclick` внутри окна. После его `onclick` окно закрывается (`Chosen`). `data-keep-open` на пункте или на предке оставляет окно открытым (проверено по коду: `Core/Popup.cs`, строка 130).
- **Клавиатура в меню.** При открытии фокус получает первый пункт (`button`, `a` с `onclick`, `data-item`; `data-item` берёт фокус и без `tabindex`). Вверх, вниз, Home, End — переходят по пунктам по кругу, если фокус на пункте; у поля ввода, `select`, ползунка, радио и многострочного поля внутри меню эти клавиши остаются их собственными (аудит D, пункт 4). Enter и Пробел нажимают пункт (как клик; окно закроется по правилу выше). Tab не выходит из меню (раздел 5.3).
- Пункт, чей `onclick` закрыл меню и открыл его снова, оставляет новое меню открытым (аудит D, пункт 10; `PopupState.Serial`).
- **`data-contextmenu="id"`** на элементе или предке: правая кнопка, нажатая и отпущенная на нём (сдвиг не больше порога), открывает окно `id` у курсора.
  - Если обработчик `SetMouse` вернул `true` на `ContextMenu`, меню не открывается: владелец открывает своё меню сам, `ShowPopup(id, e.X, e.Y, card)`.
  - Меню не открывается, если правое нажатие взял держатель захвата (`true` на `Down`), или оно пришлось на холст с обработчиком мыши (`PointerRouter.RightTaken`) (аудит D, пункт 1).
- **Слой.** Окно рисуется поверх страницы и поверх модальных `dialog` (меню внутри диалога видно). Открытие `dialog` кодом закрывает всплывающее окно.
- Рисуется из нулевого смещения, без масштаба и прокрутки предков: внутри блока со `scale` меню открывается обычного размера (по AUTHORING).

### 5.10. Перетаскивание между блоками: `data-drag`, `data-drop`, `SetDrop`

Карточку берут левой кнопкой и бросают на другой блок страницы. Без клона: двигается сам элемент (по AUTHORING; `Core/DragDrop.cs`).

```html
<div class="card" data-drag="item" data-drag-value="{{c.id}}" data-drag-name="cards">…</div>
<div class="slot" data-drop="item note" data-drop-name="slots"></div>
```

```csharp
window.SetDrop("slots", e =>
{
    // e.Phase: Enter, Over, Leave, Drop, Cancel; e.Kind, e.Value (data-drag-value), e.Source (карточка), e.Target (блок с data-drop),
    // e.X/e.Y (экран), e.LocalX/e.LocalY (точка в блоке-приёмнике), e.Ctrl/e.Shift/e.Alt
    if (e.Phase != UiDropPhase.Drop) { return true; }
    return Put(e.Target.GetAttribute("data-slot"), e.Value);   // true: принято
});
window.SetDrop("cards", e => { if (e.Phase == UiDropPhase.Cancel) { Reset(e.Source); } return true; });  // источник узнаёт об отмене
```

(проверено по коду: `Render/UiWindow.cs`, строки 395–402; `Core/DragDrop.cs`, перечисление `UiDropPhase`: `Enter`, `Over`, `Leave`, `Drop`, `Cancel`.)

- Один обработчик на имя (как `SetMouse` и `SetKeys`). Имя приёмника — `data-drop-name`; имя источника — `data-drag-name` (получает только `Cancel`).
- `data-drop` перечисляет виды через пробел; `*` берёт любой. Приёмник под указателем ищется вверх по предкам; блок, который не берёт вид, пропускается (смотрится внешний).
- **Начало:** нажатие на элемент с `data-drag` (или внутри него) и сдвиг дальше 4 px. Нажатие на `input`, `textarea`, `select`, `slot` и отключённый элемент не начинает перетаскивание. Если нажатие взял обработчик `data-mouse` (`true`) или полоса прокрутки, перетаскивания тоже нет.
- **Состояния для CSS:** `:dragging` у источника; `:drag-over` у приёмника под указателем, только если он берёт вид. Пример: `.slot:drag-over { border-color: #40c8be } .card:dragging { opacity: .7; z-index: 50 }`.
- **Призрак** — сам источник, сдвинутый числовым `translate` (`SetTranslate`) за указателем. Его CSS-`translate` на время жеста заменяется, потом возвращается. Предки с `overflow: hidden` его обрежут: поднимайте `z-index` в `:dragging`. Внутри масштабированного блока смещение указателя делится на масштаб предков (`DragDrop.GhostShift`), собственный CSS-`translate` карточки остаётся (аудит D, пункт 2).
- **Что под указателем:** элемент без источника (источник на время проверки уходит за экран). Под курсором всегда настоящий элемент, а не призрак. `:hover` замирает, подсвечивается `:drag-over`.
- **Значения** `data-drag` и `data-drag-value` запоминаются в начале жеста: все события, включая `Cancel`, несут их (аудит D, пункт 8).
- **Конец:** отпускание над приёмником, берущим вид, шлёт `Drop`; `true` принимает. Любой другой исход (отпустили мимо, `false`, Esc, источник пропал, диалог закрыл окно) шлёт `Leave` (если был над приёмником) и `Cancel` источнику. Приёмник без обработчика отказывает.
- `Esc` отменяет перетаскивание, и только его (по AUTHORING).
- `onclick` элемента после перетаскивания не вызывается, даже если кнопку отпустили позже Esc (по AUTHORING).
- Исключение в обработчике снимает его и считается отказом. Ответ на `Enter`, `Over`, `Leave` и `Cancel` игнорируется (по AUTHORING).
- Приёмник, пропавший или закрытый диалогом посреди жеста, получает `Leave` и теряет `:drag-over`. Если обработчик в кадре отпускания закрыл окно или отменил жест, `Drop` не приходит.
- **Не смешивать** с ячейкой игры `<slot>`: тот жест ведёт игра. Бросок предмета игры на блок HTML не сделан (по AUTHORING).

### 5.11. Блокировка управления персонажем

(проверено по описанию в AUTHORING и аудите D, раздел «Окна без новых возможностей»; (не проверено в игре).)

- Управление персонажем отключается: во время перетаскивания (мышь всего экрана у окна) и пока фокус в поле ввода (клавиатура у окна).
- Клик по кнопке, флажку, радио, ползунку без `tabindex` фокуса не берёт и персонажа не останавливает.
- Окно, которое не имеет фокуса и не тащит, персонажа не блокирует.

### 6.1. Набор рисования: `Window.Drawing` в `SetCanvas`

`Window.Drawing` (тип `UiDraw`, `Render/UiDraw.cs`) — то же, чем рисуют сами `<curve>`, `<chart>`, `<gauge>`. Текстуры (линии, круги, уголки) — в бюджете окна (раздел 10) и освобождаются через кладбище.

| Метод | Что рисует |
|---|---|
| `Stroke(sb, path, width, color, corner, dashOn, dashOff, continuePhase)` | ломаная; стыки круглые; прямые углы скругляются четвертью кольца радиуса `corner` (px); `dashOn`/`dashOff` в px — пунктир с бегущей фазой; `continuePhase` продолжает фазу предыдущей линии |
| `Dots(sb, path, radius, color)` | точки в вершинах пути |
| `Disc(sb, center, r, color)` | круг (радиус в целых пикселях) |
| `Ring(sb, center, outer, inner, color)` | кольцо |
| `Arc(sb, path, cx, cy, r, a0, a1, width, color)` | дуга толщины `width` |
| `Sector(sb, cx, cy, r, a0, a1, color)` | сектор |
| `Area(sb, curve, baseY, color)` | сплошная область под кривой до `baseY` |
| `Fill(sb, outline, color)` | любой многоугольник |
| `Text(sb, fonts, style, text, x, baseline, color, align)` | текст шрифтом движка; `align` — `'l'`, `'c'`, `'r'`; `fonts` — `Window.Fonts` (публичное свойство `UiWindow.Fonts` с 2026-11-16, раньше `internal`), `style` — `Window.Find("id").Style` (`ComputedStyle` элемента) |
| `Line(sb, a, b, width, color, cap)`, `Segment(…)`, `Bent(…)` | отрезки и ломаная с углом |
| `Outline(sb, rect, t, color, dashOn, dashOff)`, `FillRound(sb, rect, r, color)`, `RingRound(sb, rect, r, t, color, dashOn, dashOff)` | прямоугольники с радиусом, рамка, пунктир |

Углы в `Arc` и `Sector` — в радианах: 0 — вверх, по часовой.

Замечания (проверено по коду и по AUTHORING):

- Градиента у `UiDraw` нет (по AUTHORING).
- `UiPath` — путь: заполняйте `path.Raw` (список `DPt` в пикселях холста) и переиспользуйте список. Геометрия пересчитывается только при смене точек, ширины или радиуса; устоявшийся кадр без изменений не выделяет памяти (по AUTHORING).
- `UiDraw` получает бюджет текстур окна (`TextureLedger`); `BeginFrame` вызывает окно (частота вызова по коду не проверена).
- `DashPhase` — фаза пунктира (свойство `UiDraw.DashPhase`).

```csharp
var line = new UiPath();
Window.SetCanvas("pad", (sb, r) =>
{
    line.Raw.Clear();
    line.Raw.Add(new DPt(0, r.Height)); line.Raw.Add(new DPt(r.Width / 2, 0)); line.Raw.Add(new DPt(r.Width, r.Height));
    Window.Drawing.Stroke(sb, line, 2, new Color(63, 182, 168), corner: 8);

```

Картинки для холста — `Window.Images` (раздел 8.4; `Draw`, `DrawRegion`, `Get`, `Add`, `Peek`, `Release`, `Clear`; форматы PNG, JPG, BMP, GIF, TGA через загрузчик игры — по AUTHORING). `ImageFit` — `Contain`, `Cover`, `Stretch`, `Actual`, `ScaleDown` (проверено по коду: `Core/ImageLayout.cs`, строка 8; `ScaleDown` — то же, что `object-fit: scale-down`, с 2026-11-16 описан в AUTHORING).

### 6.2. `<curve>`: редактируемая кривая

```html
<curve data-model="settings.damageByDepth" x-min="0" x-max="5000" y-min="0" y-max="3" snap="250 0.1" mode="smooth" monotone max-points="8"></curve>
```

(по AUTHORING; `Render/UiCharts.cs`, `Core/CurveEditor.cs`, `Shared/PointCurve.cs`.)

- Значение — текст `x:y, x:y` (как `BBE.Curves.PointCurve`; игра читает его тем же разбором). Без `data-model` — атрибут `value`.
- Значение может быть списком точек (с 2026-11-16, `CurveSource` в `Core/ChartModel.cs`, `Read`/`Write`; проверено по коду): список или массив, элементы — `DPt`, пара `(x, y)`, массив или список из двух чисел, словарь с ключами `x`/`y` (или `X`/`Y`), объект с числовыми свойствами `X`/`Y`. Правка пишется той же формы: список правится на месте (растёт и укорачивается), массив той же длины — на месте, другой длины — новый массив того же типа. Модель другой формы не читается: кривая пустая (в журнал пишется строка, `UiCharts.cs`, строка 360). Тесты формы — `tools/ui_test/ChartLaneTests.cs` (группа «chart lane»: список, массив, пары, словари, объекты с `X`/`Y`, плохие элементы, NaN); (не проверено в игре).
- `mode`: `linear` (по умолчанию), `smooth` (монотонная, без перелётов), `step` (значение держится до следующей точки). Режим в тексте не хранится.
- Атрибуты диапазона: `x-min`, `x-max`, `y-min`, `y-max`; `snap="sx sy"` — шаг сетки; `monotone` — `y` не убывает; `max-points` (по умолчанию 16), минимум две точки.
- **Мышь:** тянуть точку; двойной щелчок на пустом месте — новая точка; правый щелчок по точке — убрать.
- **Клавиатура** (Tab встаёт на кривую): стрелки двигают выбранную точку на шаг сетки (без `snap` — сотая часть диапазона); Delete или Backspace убирает точку.
- Правила: первая и последняя точки сохраняют свой `x` (двигаются по `y`); точки не обгоняют соседей; `y` в `[y-min, y-max]`.
- События: `oninput` — на каждое движение; `onchange` — при отпускании, на добавление, удаление и шаг стрелкой.
- Вид (CSS): `--series-1` цвет линии, `--stroke-width` толщина, `--point-size` диаметр точки, `--point-color` цвет точек, `--series-2` кольцо выбранной точки, `--grid-color` сетка, `background-color`, `border`, `height`.
- Не проверено: клавиши кривой в игре (`ui_host` клавиш фокусу не доставляет; самотест игры их проверяет — (не проверено в игре)).

### 6.3. `<chart>`: график по данным модели

```html
<chart data-series="доход: stats.income; расход: stats.loss" type="area" format="0" y-min="0"></chart>
```

(по AUTHORING; `Render/UiCharts.cs`, `Core/ChartScale.cs`.)

- `data-series` — ряды `имя: путь` через `;`. Путь читается как в `data-model` (список чисел). Числа не из списка пропускаются.
- `type`: `line` (по умолчанию), `area`, `bar` (столбики с округлыми концами), `step` (проверено по коду: `ChartScale.cs`, строка 120).
- Оси: деления «круглые» (1, 2, 5 × 10ⁿ); ось расширяется до целых делений. `y-min`, `y-max` задают границы явно. `format` — формат `.NET` подписей (`0`, `0.0`, `0 %`).
- Ось X (внизу, только если задана; с 2026-11-16, `UiCharts.cs`, строки 470–475; проверено по коду): `x-labels="model.path"` — подписи категорий, список строк (при тесноте показывается каждая n-я); либо `x-min`/`x-max` — круглые числовые деления от `x-min` до `x-max`, категории равномерно между ними (по умолчанию `x-min` = 0, `x-max` = число точек − 1). Если заданы и `x-labels`, и `x-min`/`x-max`, побеждают подписи категорий.
- Наведение: вертикальная линия и подсказка со значениями всех рядов.
- Щелчок по точке (столбику) вызывает `onpick`; индекс точки пишется в атрибут `data-picked` и передаётся обработчику как `$arg` (`onpick="pick($arg)"`; проверено по коду: `UiCharts.cs`, строки 669–670; с 2026-11-16).
- Смена данных плавная: ряды догоняют новые значения за долю секунды.
- Вид (CSS): `--series-1`…`--series-6` цвета рядов, `--stroke-width`, `--grid-color`; подписи — `color` и шрифт элемента.
- Не сделано: градиентная заливка, логарифмические оси, масштабирование колесом, фокус с клавиатуры на `chart` и `gauge` (по AUTHORING).

### 6.4. `<gauge>`: прибор

```html
<gauge data-model="sub.depth" min="0" max="700" zones="500" ticks="8" format="0"></gauge>
<gauge data-model="reactor.load" min="0" max="100" zones="60, 85" fill="sector"></gauge>
```

(по AUTHORING; `Render/UiCharts.cs`, `Core/GaugeMath.cs`.)

- Значение — число по `data-model` (без модели — атрибут `value`), зажатое в `[min, max]`. Стрелка плавно догоняет значение.
- `zones` — пороги по возрастанию через запятую: ниже первого порога — зона 0, от порога — следующая. Цвет стрелки и дуга зон — по зоне значения.
- `fill="sector"` — заполненный сектор до значения вместо только стрелки.
- `ticks` — число делений (по умолчанию 5); `format` — подписи делений и значения.
- Дуга от −135° до +135° (от вершины по часовой); высота элемента делится под дугу и подпись значения.
- Вид (CSS): `--zone-0`…`--zone-3` цвета зон, `--needle` стрелка, `--track-color` и `--track-width` дуга, `--tick-color` деления.

По AUTHORING и `docs/HANDOFF.md`:

- Не проверено: клавиши кривой; сама игра.
- Выделения (с 2026-11-16, лейн H): кадр без изменений данных не выделяет память — значения читаются в буферы, подписи и подсказка пересобираются только при смене шкалы, индекса наведения или данных; проверка байтов на горячем пути — `tools/ui_test/ChartLaneTests.cs` (проверено по коду и тестам; в игре не измерено).

| `affliction:` | значок недуга | `AfflictionPrefab` |
| `ui:` | значок интерфейса игры | именованный спрайт стилей (`GUIStyle.Sprites`), иначе первая картинка стиля компонента (`GUIStyle.GetComponentStyle`) |

Примеры: `ui:speechbubbleicon`, `ui:outposticon`, `ui:wreckicon`, `ui:enemyicon`, `ui:guibuttonsettings` (по AUTHORING). Нет такого спрайта — одна строка в журнале, значка нет. Нарезанный спрайт даёт всю картинку, а не девять частей (`UiSprites.cs`, комментарий).

Где использовать: `<item sprite="item:oxygentank">`, `background-image: sprite(ui:имя)`, `<img src="sprite(item:oxygentank)">`, `border-image-source: sprite(ui:имя)` (последний режется срезом целиком; девять частей игры не берутся, по AUTHORING).

### 7.4. Символы Юникода в JetBrains Mono

По AUTHORING (проверено по таблице символов шрифта, `cmap`; в этой сверке не перепроверено):

- Есть: `▲ ▼ ► ◄ ▶ ◀ ✓ ✗ ✕ × ⚠ ● ○ ■ □ ◆ ◇ ← → ↑ ↓ ≡ … • –`.
- Нет (пустой квадрат или пропуск): `★ ☆ ♥ ✔ ✘ ⚙ ☰ ⌕ ✖`.
- Размер, цвет, `text-shadow` и `scale` работают как у текста. Для других семейств (`font-family: serif` и т.п.) набор меньше; запасной шрифт для пропущенных символов не проверен (по AUTHORING: что рисуется вместо них, неизвестно).

### 7.5. Картинки-значки

Растровый лист: `background-image: url("icons.png")` с `background-position` и `background-size`, как лист спрайтов: блок размером с значок, `background-position: -32px -64px`, `background-repeat: no-repeat`. Мягчает при масштабе (по AUTHORING).

Другие иконочные шрифты (Material Symbols, Phosphor) не подключены. Lucide закрывает то же.

### 7.6. Русская склейка

Неразрывные пары для русского текста (`-bbe-ru-glue`) описаны в разделе 4.6.4a.

## 8. C#-API: публичные типы и члены

Пространства имён: `BaroUI.Api` (`BaroUi`, `BaroUiView`), `BaroUI.Core` (разбор, стили, ввод, геометрия), `BaroUI.Render` (`UiWindow`, рисование, контролы). Все перечисленные члены проверены по коду (`own/BBE_UI/CSharp/Client`), если не указано иное.

Стабильный публичный API (по одной строке на член), версия движка и правила ломающих изменений: [`API.md`](API.md). Проверка версии в моде: `BaroUi.Requires("0.2.0", имя)`.

### 8.1. `BaroUi` (статический, `Api/BaroUi.cs`)

| Член | Что делает |
|---|---|
| `Open(string htmlPath, BaroUiView view = null, string name = null)` → `UiWindow` | открыть свободное окно; обновляется и получает ввод |
| `Open<T>(string htmlPath, string name = null)` → `T` | то же с новым экземпляром `T : BaroUiView` |
| `Create(string htmlPath, BaroUiView view = null, string name = null)` → `UiWindow` | окно предмета: владелец сам добавляет его в список обновления и закрывает |
| `OpenPage(string page)` → `UiWindow` | открыть `UI/<page>.html` текущего пакета (или папки из `baroui src`) |
| `Windows` → `IReadOnlyList<UiWindow>` | открытые свободные окна |
| `Version` → `System.Version` | версия движка (0.2.0), одна константа; то же число в `filelist.xml` |
| `Requires(string minVersion, string modName)` → `bool` | проверка при старте: при старой версии одна строка в журнале и `false` |
| `Reload(UiWindow w)` → `string` | перечитать HTML и CSS на месте |
| `event Action<UiWindow, UiWindow> Reloaded` | окно заменено перезагрузкой (порядок аргументов — (не проверено по коду)) |
| `Watch` (bool) | перезагрузка при сохранении и плашка ошибок |
| `Animations` (bool) | все анимации окон вкл/выкл |
| `LayoutFps` (float, по умолчанию 30) | общая частота выборки длин (`layout-fps: auto`); `0` — каждый кадр (`baroui anim fps N`, `Api/BaroUi.cs`, строка 23; проверено по коду) |
| `PackageDir`, `PageDir` | папка пакета и папка страниц |
| `Fonts` → `UiFonts` | шрифты окон |

Внутренние (не для страниц): `Init`, `Dispose`, `Forget`, `AfterDraw`, `PauseMenuPrefix`, `AddWindowsPrefix`, `NavigateByInput`, `SideBackPrefix`, `SideForwardPrefix`, `SourceOverride` (`internal`).

Модель открытой страницы из файлов: `BaroUi.OpenPage(page)` (`baroui open <page>`) берёт модель из `UI/<page>.data.json` рядом со страницей, если вид окна модели не дал (проверено по коду, `Api/BaroUi.cs`; читатель — `Core/JsonModel.cs`). Для `inputs` модель даёт самотестовый `InputsView`, поэтому там файл в игре не используется, а `ui_host --data` читает его. `pseudo_demo.html` моделей не читает, файла нет.

| Член | Что делает |
|---|---|
| `Get(string path)` → `Texture2D` | картинка из файла; один раз на файл; нет файла или битый — `null` и одна строка в журнале. Файл проверяется раз в секунду (`RecheckEvery = 1.0`), сохранён заново — читается заново |
| `Add(string key, byte[] encoded)` → `Texture2D` | картинка не из файла (вставленная, раздел 5.7) |

`ImageFit`: `Contain` (вся, по центру), `Cover` (заполнить, края срезать), `Stretch`, `Actual` (1:1 по центру), `ScaleDown`.

`pixelPerfect`: целые масштабы без сглаживания (пиксель-арт). Пакет рисования переоткрывается на время вызова: давайте несколько больших картинок, а не сотни мелких (по AUTHORING).

## 9. Инструменты

### 9.1. Команды консоли игры

(проверено по коду: `Api/BaroUi.cs`, `OnCommand`, строки 210–283; команда `baroui`.)

| Команда | Что делает |
|---|---|
| `baroui open <page>` | открыть `UI/<page>.html` |
| `baroui close [page]` | закрыть окно страницы или все окна |

| `baroui debug [on\|off]` | контуры всех блоков; под мышью — поля (оранжевые), отступы (зелёные), содержимое (синее), селектор, размеры в u и px, строка в HTML; плашка ошибок |

Переключатели: `on`, `1` — включить; `off`, `0` — выключить; без аргумента — переключить (внутренняя функция `Toggle` в `Api/BaroUi.cs`).

### 9.2. Watch, debug, problems

- `watch` опрашивает файлы страниц (`PollWatch`) и перезагружает изменённые; ошибки — плашкой. Частота опроса — (не проверено по коду).
- `debug` включает `UiDebug.Outlines` (раздел 9.1).
- `problems` печатает `w.Problems` всех окон или одного (`Core/Dom.cs`, `Diagnostic.ToString()`: `файл:строка: текст`).
- Замечания: каждая неподдерживаемая вещь в CSS — замечание (`CssParser`, `StyleEngine`), неизвестный `data-t`, неизвестный `prefab`, `background-repeat` сверх предела и т.п.

### 9.3. `tools/ui_host` и эталонные снимки

- `tools/ui_host` — консольный хост (`ui_host.csproj`, `Program.cs`, `ModsScenario.cs`, `Script.cs`; `--data` читает `own/BBE_UI/CSharp/Client/Core/JsonModel.cs`, тот же код, что `OpenPage`). Рисует страницы настоящим `UiWindow` и `Painter` в PNG; шрифт Noto Sans берётся из папки игры (только чтение) (по AUTHORING; проверено по составу папки).
- Сборка: `cd tools/ui_host && dotnet build -c Release && cd ../..` (по AUTHORING).
- Ключи: `--page <файл>`, `--data <json>`, `--frames N` (по AUTHORING и `snap.py`).
- Ограничение: `ui_host` не доставляет клавиши фокусу (AUTHORING, раздел «Графики»).
- `tools/ui_host/snap.py` — сравнение снимков:
  - `PAGES` — список страниц: `controls`, `inputs`, `anim_demo` (из `own/BBE_UI/UI`), `dialog` (`own/BBE_Dialog/UI/dialog.html`) и `toast` (`own/BBE_Toast/UI/toast.html`; это другие пакеты, не `BBE_UI`).

### 10.9. Что стоит дорого

| Что | Почему | Что делать |
|---|---|---|
| `:has()` над большим поддеревом | при каждом перестиле контейнера проверяется поддерево; `.map:has(.x)` над 6000 элементами — до 6000 проверок (`PERF.md`, «Псевдоэлементы и :has()») | `:has(> .x)` (только дети) или правило на сам элемент |

| `font-size` каждый кадр | каждый новый размер — новый шрифт игры (около 8 МиБ) | `scale` для плавного увеличения (шрифты под масштаб выгружаются) |
| переходы длин (`width`, `height`, отступы) на больших блоках | каждое значение длины — пересчёт раскладки блока, по сетке `layout-fps` | `transition: layout` для раскрытия; `opacity` и `translate` для остального |

| `resize` карточки в карте (полная перепечатка слоя) | родитель `#world` попадает в грязные корни (45–65 мс, Debug) | упрощённый вид при малом масштабе; нужен ли он, решает владелец (`PERF.md`, B3; решения нет) |
| `dialog`, `select` внутри `scale` | открываются без масштаба, прочее — отдельные пути | открывать вне масштабируемого блока |
| `canvas` с большим числом вызовов рисования | не измерено | (не проверено) |

## 11. Чего нет, пределы и что не проверено

### 11.1. Список «нет»

Проверено по коду: этих имён нет в `StyleEngine.Initial`, `Shorthands`, `CssValues`, `CssParser`, `HtmlParser`, `UserAgentCss`, или поведение явно не реализовано. Для каждого свойства — неизвестное, с замечанием.

**Функции и единицы CSS**

- `calc()`, `min()`, `max()`, `clamp()`, `var()` внутри функций (кроме простой подстановки `var(--x)`).
- Единицы: `rem`, `vw`, `vh`, `vmin`, `vmax`, `ch`, `ex`, `pt`, `cm`, `in`, `Q`. Есть только `px`, `u`, `em`, `%`, `fr`, `auto`, `0`.
- Цвета: `hsl()`, `hwb()`, `lab()`, `lch()`, `color-mix()`, `color()`. Есть `rgb()`, `rgba()`, `#…`, имена.
- `counter()`, `counters()`, `attr()` вне `content`, `url()` в `content`.

**Правила и селекторы**

- `@media`, `@import`, `@font-face`, `@supports`, `@layer`, `@container`, `@namespace`. Есть `@keyframes`.
- Операторы атрибутов: `[a^=…]`, `[a$=…]`, `[a*=…]`, `[a~=…]`, `[a|=…]`.
- Псевдоэлементы, кроме `::before`/`::after`: `::marker`, `::selection`, `::placeholder`, `::first-line`, `::first-letter`.
- Псевдоклассы: `:link`, `:visited`, `:empty`, `:is()`, `:where()`, `:first-of-type`, `:nth-of-type`, `:lang()`, `:target`, `:scope`, `:required`, `:invalid`, `:placeholder-shown`, `:nth-child(2n+1)` (`an+b` не разбирается, совпадения нет).
- Списки в `:not(...)` и `:has(...)`, вложенные `:not` и `:has`, псевдоэлементы в их аргументах.
- Два комбинатора подряд.

**Свойства, которых нет** (см. также раздел 4.6.10)

- `float`, `transform` (кроме `translate` и `scale`), `filter`, `backdrop-filter`, `clip-path`, `mask`, `mix-blend-mode`, `will-change`, `user-select`, `inset`, `aspect-ratio`, `font` (сокращение), `grid-row`, `grid-area`, `justify-items`, `justify-self`, `place-*`, `object-position`, `background-clip`, `background-attachment`, `background-origin`, `word-break`, `hyphens`, `text-wrap`, `text-align-last`, `text-justify`, `direction`, `writing-mode`, `font-variant`, `font-stretch`, `list-style`, `counter-reset`, `counter-increment`, `border-top-style` (и по сторонам), `transition-behavior`, `animation-composition`, `animation-play-state`.

**Значения, которые принимаются, но не делают того, что в браузере**

- `display: table`, `table-row`, `table-cell`, `list-item` — блок с замечанием; `<table>` не таблица.
- `overflow: clip` — ведёт себя как `hidden`.
- `border-style: double`, `groove`, `ridge`, `inset`, `outset` — сплошная линия.
- `text-decoration-style` кроме `solid` — сплошная линия.
- `outline-style: dashed`/`dotted` — сплошная линия.
- `text-shadow` с размытием — резкая тень; список теней — первая.
- `box-shadow`: только одна внешняя; `inset` — нет.
- `background-image`: `conic-gradient`, `repeating-*`, подсказки цвета, радиус в `%` у радиального градиента — нет (градиент не рисуется, предупреждение).
- `vertical-align` и `-webkit-box-orient` — без действия.
- `transform-origin` — без действия (центр масштаба — левый верхний угол).
- `text-align` — только `left`, `center`, `right`.
- `line-clamp` на блоках `inline-block` в отброшенных строках — не скрываются (аудит C, пункт 12).
- Цвет `currentcolor` у тени текста берётся по кадру (это работает), но тень не анимируется.

**Рисование и картинки**
